今天还剩什么，Jarvis 看你的日历和待办来答；昨天做了什么，她看自己每天早上根据你的记录写好的一份日报来答。

## 看今天还剩什么

首页有个「今天」区块：今天的日历日程、所有没做完的待办，设了位置的话还有天气。它直接读你的 Outlook 日历和 Microsoft To Do，中间不经过语言模型，所以很快，也和那两个 App 里看到的完全一致。在这里勾掉一条待办，就是在 Microsoft To Do 里勾掉；这一下点击是这个区块唯一会写的东西。

你也可以直接问她。对话里，日历和待办的读取工具从一开始就摆在她手边。

## 用早报看昨天

每天清晨（默认 05:00），守护进程会把前一天的日报写好。它读那天的对话记录和 git 提交，打开了屏幕活动记录的话还有屏幕活动，再加上你的日历和待办。你当天早上第一次打开首页，会看到一张「早报」卡片，给出昨天的主线；点开能看到做了什么、还没完成什么、你说过的下一步和定下来的事。用语音问她昨天的事，她也是从同一份存好的日报里回答。

日报只按时写，从不按需现写。按需写的版本在测试里试过：一句语音问下去，接着是将近一分钟的沉默。

## 她说「完成」，凭什么

这份日报的设计原则是不夸大。模型先起草，但「完成」只是一个声称：没有引用的声称，程序直接判无效；一个提交只算「已提交」，说「已合并」得看那个提交确实在 main 上，说「已部署」不能只靠一个提交。剩下的声称，再由另一次独立的模型调用对照被引用的原文逐条下结论。编码代理自己说做完了，日报会写成「据代理自述已完成，尚未核实」。

核不了的声称，也会如实写出来。早报里每一项的结论是一个标签：已完成、部分完成、进行中、未核实、讨论、浏览。

## 从一行顺着找回原始记录

存下来的日报里，每个工作事项末尾都有带编号的引用，文末的「证据引用」说明每个编号是什么：一条对话记录、一个 git 提交、一个截下来的窗口。她能把任何一条背后的原文调出来。早报页是给人读的精简版，引用被去掉了：标签带着结论，完整日报带着证据。

## 她读什么，哪些默认关着

读别的 App 的数据都要你自己打开。屏幕活动来自另一个独立的记录工具 TimeSink，不打开就不读；Codex 的对话默认不读；日报根本不读 Claude Code 的会话。日历和待办只有连了 Microsoft 账号才会出现。

日报由 OpenAI 的模型来写，所以那一天的材料（打开屏幕活动时包括屏幕文字）会发给它。规格文档里逐项列了什么发给谁。
