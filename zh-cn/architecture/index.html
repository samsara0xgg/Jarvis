它是怎么搭起来的

Jarvis 是一个大脑加几个身体。大脑是一个 Python 守护进程，Mac 伴侣应用和 iPhone、iPad、Apple Watch 的应用是它的身体；守护进程的代码分了层，层与层之间不许越界。这一页是地图；设计笔记把其中四个决定写成了小故事。

一个大脑，几个身体

Section titled “一个大脑，几个身体”

大脑管记忆、事件日志、模型调用和工具，其他设备都是它的终端（ADR 0170）。它可以跑在家里的树莓派上，设备只通过私有网络连它。每个身体各自带麦克风、唤醒词和扬声器。iPhone、iPad 和手表的应用是原生 SwiftUI；iPad 还能显示并操控你 Mac 的屏幕（Jarvis Remote）。下面这一页讲的是守护进程和 Mac 伴侣应用。

守护进程和伴侣应用

Section titled “守护进程和伴侣应用”

守护进程是 Python 3.12，而且分角色。config/jarvis.yaml 里的 runtime.role 是 all（一台机器包办一切，默认）或 brain；只负责说和听的设备跑另一个入口，终端（ADR 0170）。树莓派上的大脑是无头的：管状态、模型请求和调度，不碰麦克风和扬声器，也不会把绑定设备的工具交给模型。终端（比如 Mac）自己留着麦克风、回声消除、唤醒词、断句和播放，大脑把合成的语音流给它。模型的密钥只留在大脑上。

终端通过 WebSocket 连大脑：Mac 走 /terminal/ws，手机走 /phone/ws。大脑只听本机回环地址和它的 Tailscale 地址，从不听 0.0.0.0，远程设备要带自己那份配对令牌才放进来。

伴侣应用用 Electron、React 19 和 TypeScript，再加一个很小的 AppKit 模块（Objective-C++）来画那团玻璃。Mac 屏幕上你看得见的东西归它：刘海旁的小球、Dashboard、首次设置和设置页。它不带模型，也没有记忆。打开 Agents 窗口时，旁边还会起一个小的 Node 宿主，让你的 Claude Code 和 Codex 会话在重启之后还能接着跑。iPhone、iPad 和 Apple Watch 的应用是原生 SwiftUI。

在 Mac 上，伴侣应用通过本机回环地址、用一把每台机器各自的密钥，和本机的守护进程或终端通信。这个入口只接受发给 127.0.0.1 或 localhost 的请求（所以把自己域名重绑到你机器上的网页也进不来），除了存活探测，每个接口都要带运行目录里的那把密钥。终端自己回答少数设备上的路由，比如听写，其余转给大脑；关于你的状态，它从不拿本地数据来答。从 MacBook 量过，大脑隔着 Tailscale 中继大约 80 毫秒，回环只要 3 毫秒，所以字幕和说话的表情留在终端上。

语音这条线

Section titled “语音这条线”

每台设备各自找唤醒词。Mac 用 microWakeWord（“Hey Jarvis”）；iPhone 和 iPad 在识别器正在输出的文字里找，而且只在应用开在屏幕上时。周围有好几台设备时，由大脑在你开口之前就点名一台来回答：你正在说话的那台，没有的话就是你最后用的那台（ADR 0407）。

怎么听取决于配置。开了云端识别时，设备把每句话的音频流给大脑，大脑再流给 Qwen，并带上主人的词表作热词，服务商的密钥因此只留在树莓派上。没开，或者连不上大脑时，Mac 在本机用 SenseVoice 听，Silero 做语音活动检测。声音是 MiniMax，通过 WebSocket 流式返回。存储全程是 SQLite。

模型默认用 Claude：对话用 Sonnet，写“你当时在做什么”的 doing 通道用 Opus，频繁的后台分析用 Haiku。

三级

Section titled “三级”

守护进程的代码分三级，一个包只能 import 它下面的。

级 包 管什么 示例模块
顶 runtime 搭起进程、让它跑、驱动一轮，和要同时用到两块的代码 jarvis/runtime/turn/drive.py
块 decision Tier 0 路由、策略和闸门、每一轮发给模型的请求怎么拼、模型调用、夜里的整理和它们的时间表 jarvis/decision/gates.py
块 execution 工具、worker、插件和 MCP 客户端、浏览器护栏 jarvis/execution/mcp_tools.py
块 surface 语音、HTTP 和 WebSocket 接口、页面、推送、Claude Code 和 Codex 会话、屏幕和用量的观察者 jarvis/surface/voice_pipeline.py
块 deployment 运行目录、钥匙串、launchd、睡眠唤醒、模型下载、导出和抹掉 jarvis/deployment/launchd.py
底 state 只追加的事件日志、从中折出来的投影、memory.db、设置文件和其他本地存储 jarvis/state/event_log.py
底 shared 纯函数和静态数据：产品名、时钟、文字表、价格表。什么都不 import。 jarvis/shared/pricing.py

jarvis/cli/（入口）在 runtime 上面。

只有 runtime/ 能把几块接起来

Section titled “只有 runtime/ 能把几块接起来”

import 只能单向走。cli 可以 import runtime；runtime 可以 import 中间四块；四块可以 import state；state 可以 import shared；shared 什么都不 import。四块彼此不能互相 import：语音代码够不着工具，决策代码也够不着语音。

这条规矩由构建来执行。lint-imports 读 .importlinter 里的约定，哪个包违反就报错；它在仓库的初始化脚本里跑，也是每次提交前的一道门。另一半由一个 canary 管：只有任何一块都放不下的代码才进 runtime/，所以新代码会落在它用到的那一块。两块必须配合时，由 runtime/ 把一块的函数交给另一块。比如决策快照的缓存放在 jarvis/state/decision_snapshot_cache.py，runtime 从它拿出一个读取函数交给每一轮，决策代码不用知道它从哪来。

状态脊柱

Section titled “状态脊柱”

Jarvis 知道的一切都朝一个方向流：事件日志，再到投影，再到记忆。

  • 事件日志是一张只会变长的 SQLite 表。触发器拒绝一切 UPDATE 和 DELETE，更正只能追加新事件。每条事件记的是谁在什么时候报告了什么，事件类型登记在同一个文件里，截图、录音这类大块内容存成文件，日志里只放引用。
  • 投影是日志折出来的结果：待确认的卡片、没结束的动作、最近几轮。模型、工具和界面都不能写它。每一轮读的是折到最新事件的结果；从 ADR 0164 起，它只折上次读过之后新增的事件，结果和从头折一遍完全一样。
  • 记忆是 memory.db：逐字的对话、每天的摘要，以及夜里改写的那份关于你的、带版本的笔记。它之上的东西都是派生出来的，可以重建。

决定怎么留下来

Section titled “决定怎么留下来”

每个挪动边界或合同的决定，都留一份 ADR：到目前为止四百多份，一个决定一个文件，一份一页。其中几份公开在 docs/adr 里。规范（docs/adr/README.md）要求必须有 Alternatives rejected（被否决的方案）一节，而且落选的理由要能用一个数字或一次可复现的观察来反驳，因为只有这一部分是代码和规格里都不会写的。scripts/check_adrs.py 检查格式、状态取值、200 行上限和悬空引用。要改一个已经接受的决定，就写一份新的 ADR，把旧的标为被取代，不去改旧的。

完整规格

Section titled “完整规格”

一个公开版本必须满足什么，写在规格文档里：进程、状态脊柱、一轮怎么执行、哪些东西会离开这台 Mac、威胁和对应的护栏、密钥、生命周期。规格是中文写的；ADR 是英文写的。
