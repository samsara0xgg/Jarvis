插件

Jarvis 不去重写你每天用的 App，而是通过 MCP 连上它们。MCP 是一套开放协议，让助手能调用别的服务提供的工具。每个插件在你打开之前都是关着的。

它能连上哪些账号？

Section titled “它能连上哪些账号？”

仓库里自带四个插件，第五个连接靠配置接入。

  • Gmail：是 Jarvis 邮件工具底下的连接。它在你的 Mac 上运行 Google 的 Workspace MCP server，只开了 Gmail 这一组功能。邮件怎么读、怎么起草、怎么发送，见邮件页。
  • GitHub：通过 GitHub 官方托管的 server 处理仓库、issue、pull request 和 CI。
  • Notion：通过 Notion 托管的 server 读写页面和数据库，另带四个技能：写规格、做调研、准备会议、沉淀知识。
  • Philips Hue：开关、调亮度、切场景。它只和你家局域网里的 bridge 通信。
  • Microsoft To Do 和 Outlook 日历：它们不在 plugins/ 目录里，而是靠你自己在配置里加一个 Microsoft MCP server，之后会出现在同一个插件列表里；你自己加的其他 MCP server 也一样。

怎么打开一个插件？

Section titled “怎么打开一个插件？”

要你自己来，没有任何东西会自己启动。出厂时一个插件都没有启用。如果你让它在一个还没连上的 App 里办事，它可以把插件面板打开，但登录要等你自己开始，后台进程从不会自己弹出浏览器。令牌和 key 不会进对话。托管 server 的 OAuth 令牌（比如 Notion 的）存在各自的文件里，文件放在只有你的账户能打开的目录中，也只有你的账户能读。其他的 key（比如 GitHub 和 Hue 的）存在 macOS 钥匙串里，没有钥匙串的机器上则存在一个私有文件里。Gmail 的令牌不由 Jarvis 保管：Google 的 server 把它加密存在自己的目录里。

它动手之前会做什么？

Section titled “它动手之前会做什么？”

读东西它直接读，改东西之前先问你。每个工具按 server 自己声明的提示分类：只读的立刻执行；会删除、发送、合并，或者不能确定无害的，会变成一张确认卡，等你按按钮。只有 server 同时标明“不破坏”和“不碰外部世界”的写操作，才不用问。

你也可以按插件调整：总是问、只问写操作、或者从不问。Hue 是个好例子：查看灯的状态是预先批准的，开关一盏灯则要先问，除非你放宽。

它怎么找到该用的工具？

Section titled “它怎么找到该用的工具？”

靠搜索。像 GitHub 这样的 server 会列出几十个工具，每次请求都全带上，既花钱又拖慢每一轮。所以插件的工具默认不在它的菜单上，要用时由一个叫 tool_search 的工具按名字、描述和参数去找。找到的工具只在这一轮有效；命中一个工具时，同一个 server 的只读工具也会一起带上，因为光搜不读往往没用。你问得最多的日程和待办读取一直放在菜单上，这几类问题就省掉了搜索这一步。Gmail 有自己的工具放在菜单上，所以邮件问题从不需要先搜工具。

你的数据去了哪里？

Section titled “你的数据去了哪里？”

每个插件只和它自己的服务通信。它在对话里读到的内容，比如一封邮件，会和对话里的其他内容一样发给模型服务商。插件没有签名，也不声明自己需要什么权限，所以打开一个插件，就是选择信任它。
