# 报告格式

## `report_daily_work` 各字段

- `summary`：核心摘要，2 到 6 句，说清这一天主要围绕什么、有哪些实质进展和结果。
- `items`：按工作事项归并，同一件事的多次活动合成一项。每项：
  - `title`：事项名（不超过 60 字）。
  - `status`：`browsed` 浏览 / `discussed` 讨论 / `attempted` 尝试或进行中 /
    `completed` 完成。只有 Git 提交或 Allen 本人陈述能支撑 `completed`。
  - `activity`：做了什么、产出了什么、进展到哪一步；写事实，不写评价。
  - `refs`：支撑这一项的材料键。
- `decisions`：重要决定和方案变化。`rationale` 只在材料里有依据时填，否则为 null。
- `open_items`：未完成事项、阻碍、待确认的问题。
- `user_next_steps`：Allen 明确表达过的下一步，必须引用他本人的记录键。
- `suggestions`：你根据材料提出的建议，和 Allen 的承诺分开。
- `uncertainties`：不确定之处、证据冲突、材料缺口。

## 保存的报告版式（由运行时组装）

```
# 工作日报 <日期>（<时区>）
生成时间、证据窗口、模型

## 核心摘要
## 工作事项
### 1. <事项> — <状态>[依据说明]
<活动与进展>
引用：<来源引用>
## 重要决定与方案变化
## 未完成、阻碍与待确认
## 用户明确表达的下一步
## 建议（模型提出，非用户承诺）
## 数据覆盖与不确定性
## 证据引用
```

依据说明由运行时按引用自动标注，标的是来源种类，不代表来源支持这条结论：当天的 Git
提交或 Allen 陈述为"有据"；只有屏幕或应用记录为"仅屏幕/应用依据"；没有有效引用为
"推断"。标为完成但无上述来源的事项会被标为未证实，并写进核心摘要的核对提示。
