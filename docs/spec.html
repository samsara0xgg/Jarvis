这份 spec 写 Jarvis 的公开版必须满足什么：给谁用，由哪些进程组成，状态怎么存，什么时候能动手，什么会离开这台 Mac，防什么，钱怎么花，怎么接 Claude Code 和 Codex，怎么装、更新和卸，什么时候开口。为什么这样定写在 ADR 里。单个功能的接口、字段和界面细节由定义它的代码和测试负责，这里只收别的程序要依赖的格式，和主人要知道什么离开了 Mac 时需要的清单（ADR 0089）。

怎么引用。用锚点，例如 docs/spec.html#egress，不用 § 编号。代码、配置和测试里在 ADR 0089 之前写下的 § 编号指向已归档的 docs/spec-v1.html，那份只是背景。

两种标记。未满足是 ADR 已经定下、代码还没做到的规则。「现在还没有」说的是现状：要改它，先写 ADR。缺口后面的「改N」「包N」是《Jarvis 发布清单》的条目编号，进度记在那里。

1. 定位与主人

一句话

给同时用 Claude Code 和 Codex 的 Mac 开发者的刘海伙伴。替主人盯着所有 agent，记住主人的一天，只在值得的时候开口。下载就能用，用主人自己的一把 key。
它是它不是
一人一份。每个 macOS 账户一个主人，主人的名字在首次设置时定下（ADR 0090）。又一个干活的 agent。写代码、操作电脑交给 Claude Code 和 Codex。
agent 的总管。派活、盯进度、收结果，审批不用切窗口。多人协作或团队工具。一个安装只认一个主人。
本地优先。状态都在这台 Mac 的运行目录里。Jarvis 没有自己的服务器，发出的请求只去主人配置的服务商、主人连上的服务，或对话里要打开的网址（见第 5 章）。云服务。不中转主人的数据，也不转售模型额度。
一把 key。默认打开的功能只用主人自己的一把 OpenAI key（ADR 0092）。智能家居中枢。房间屏幕不在这一版里；Hue 这类设备走插件（ADR 0079）。主人自己的设备可以连同一个大脑当终端（ADR 0170），但这不是同步，也不管别人的设备。

宪法

六条原则约束下面所有章节。改其中任何一条都要先写 ADR。

C1. 一台 Mac 一个主人（ADR 0090）。一个安装只服务它所在 macOS 账户的那个人：记忆、key、确认和注意力都是这个人的。它可以尽量贴合主人的项目、习惯和说话方式，但代码里不写死任何具体的人，陌生人第一次打开也要看得懂。同一台 Mac 上的两个人是两个账户、两份安装，只共享硬件。Jarvis 不分辨声音：主人的 Mac 旁边说话的人，都被当成主人。大脑和终端分开部署时（ADR 0170），一个大脑连同配对给它的终端算一个安装，主人是配对这些终端的那个人。
未满足模型读得到的文字里还写着 Allen：浏览器护栏的拒绝语、Agents 窗口回给 Claude 的拒绝语，以及日报、工作状态和压缩的提示词（改2）。存下来的记录用 allen 标记主人说的话；这个存储值可以等数据迁移再改，但后三种提示词把它原样摆在模型面前，要先换成中性的说法。本机接口认的是固定端口，不是账户（见第 2 章）。
C2. 状态才是本体。身份不在模型、提示词、工具或语音管线里，而在持续维护的状态里：只追加的事件日志，和从它折出来的投影（第 3 章）。换模型、改提示词、加工具都不动它。
C3. 少让主人重复解释。核心价值是主人不用重新装载上下文：哪个 agent 在干什么，昨天做到哪，哪些事没收尾，下一步先做什么。
C4. 总管，不是干活的。Jarvis 派活、盯进度、收结果、整理状态；写代码和改文件交给 Claude Code 和 Codex。主模型没有终端、打补丁或写文件的工具。worker 的最终消息原样转给主人，Jarvis 不替它判定做没做成（ADR 0019）。
C5. 权限越高，越要受约束、留痕迹。每个动作都过风险等级、确认和闸门（第 4 章），并留下事件。工具返回成功、agent 自报、模型自信，都不能单独算作目标达成；Jarvis 说出口的话不比它看到的更肯定。
C6. 表面可换，连续性不断。语音、刘海、面板、通知都只是表面。换语音服务商、换界面，都不能断掉状态。

Jarvis 对主人的承诺

  • 安静优先。默认不打扰，主动开口要有理由（第 10 章）。
  • 状态看得见。主人想知道的当前状态都查得到，并看得出是什么时候的。
  • 不夸大。没看到结果的事，不说成做完了。
  • 不瞒。什么会发出去、发给谁，写在第 5 章；它动过什么，事件日志里都有。

2. 系统长什么样

一台 Mac 上三个常驻进程：后台、伴侣和 agent 宿主，加上按需拉起的 keeper、Codex app-server 和 hook 脚本。它们之间只在本机说话；往外发的请求见第 5 章。进程之间的接口由说它的代码定义，不写在这里（ADR 0089）。

进程

进程做什么谁拉起、谁重启在哪听
后台（Python，python -m jarvis serve）麦克风和扬声器、本地语音模型、记忆、工具、事件日志，以及发给模型的每个请求安装版由 App 拉起，退出就重启（跑满一分钟才退出的，一秒后重启；连续崩溃时间隔翻倍，最长一分钟）；开发机上是 LaunchAgent com.allen.jarvis127.0.0.1:8006，HTTP 和 WebSocket。安装版发现 8006 被一个答不上令牌的进程占着，就换一个空闲端口
大脑（同一个 python -m jarvis serve，设置里写 runtime.role: brain，ADR 0170）无头：记忆、事件日志、模型请求、Jev、主动提醒和定时、MCP。不开麦克风、回声消除、唤醒、ASR 和播放，不拉起 Swift 播放器和环境声助手，不跑读本机文件、应用和登录的观察器（TimeSink、仓库、Claude 和 Codex 的用量、Claude Code 会话）、电源通知和夜间模式；其中 TimeSink、仓库和 Claude、Codex 用量观察器改在终端上跑，事件由终端推进大脑的日志（下一行）；用量观察器的另一半（OpenAI、DeepSeek、MiniMax，要服务商的钥匙，钥匙在大脑上）由大脑自己跑，设置里 observer.usage.enabled 为真就开，它不碰 Claude Code 和 Codex 的登录；Claude Code 会话页不读大脑自己的文件，改向终端要（claude_read：会话板、一个会话的对话页、往空闲后台会话里敲的回复），没有终端连着时板是空的并带一句「设备没连上」，对话页和回复答 502 同一句话；会话收尾是不是在问主人要用模型，仍由大脑问，问的是终端读到的收尾那段话；也不下载语音模型。时间线工具（query_activity、read_activity）、日报、工作状态、保存时对引用的核对、现况（moment）、求职台账的用时列和项目看板里，读 TimeSink 库和读本地 git 的那部分，大脑上没有这些文件，改向终端要：终端在本机用同一份读取代码读，把 JSON 结果交回，大脑用在原来用本地结果的地方，工具的名字、说明和参数不变；日志里已有的观察事件（git 行）照常读。没有终端连着时，时间线工具的应用和屏幕来源报一句明白的话（设备没连上、读不到），git 行附上覆盖说明；日报和工作状态把 TimeSink 与 git 的覆盖记为不可用并写明原因，不当作那一天什么都没发生；定时日报在终端没连上时照样按时写，覆盖记为不可用，之后一连上有读这两样的终端就把那一天补写一次（最多两次，补写不成也不再试），补好的不再补；现况的读数全是 unknown 且 read 写明原因（不拦任何提醒，和 TimeSink 关着时一样），台账和项目看板各带一句同样的话（time_note、note）；模型的工具表里仍有 open、截屏、剪贴板、读文件和 Obsidian 搜索，但它们不在大脑上执行，而是交给已连上的终端（下一行）；没有终端连着、超时或中途掉线，工具结果就是一句明白的话（如「macbook 现在没连上」）。工具的名字、说明、参数、风险和确认要求与单机一样，闸门和确认留在大脑，只有执行挪走。Codex worker 不开。终端声明要说话时（hello 里 voice: true，ADR 0172），大脑替它合成语音：语音服务商的钥匙和请求仍在大脑上，没有 MINIMAX_API_KEY 时 ready 里的 voice 为 false，不给这台终端说话；答案的行（surface.response_*、response.cancelled|failed）从它连上那一刻的日志末尾起，按日志顺序流给听见那一轮话的语音终端（不是终端听到的轮次，就流给最近连上的那台），断线重连从终端已收下的最后一行接着发，不重播旧答案；静音渠道的轮次不发，和本机扬声器一样；终端开的合成会话由大脑上的真会话执行，链路断开就中止这台终端的全部会话。runtime.role 默认 all，就是上一行的样子Linux 上由 systemd 用户单元 jarvis/deployment/systemd/jarvis-brain.service 拉起，Restart=on-failure127.0.0.1:8006，再加 runtime.listen_addresses 里的私网地址（本机接口）

本机接口

  • 后台只接受 Host 头是 127.0.0.1 或 localhost 的请求，挡住把自己域名重绑到本机的网页。除了存活探测和自带每次启动令牌的 v2 路由，每个请求都要带运行目录里 plugin-access.json 的令牌。
  • 大脑（runtime.role: brain）可以再按设置在私网地址上听同一个端口（ADR 0170）。runtime.listen_addresses 列出要多听的地址，只收私网地址（如 tailnet 的），0.0.0.0 和公网地址让启动失败；runtime.listen_hosts 列出除上一条之外多接受的 Host 名。两项默认都空，这时只听 127.0.0.1，Host 头也只认上面那两个。别的角色写了这两项，后台不启动。
  • 不在回环上的对端读不到运行目录，所以它的每个请求（存活探测除外）都要带一个已配对设备的令牌，代替上面的 plugin-access.json 令牌和每次启动的 v2 令牌，v2 的 WebSocket 和 HTTP 输入路由也一样。令牌在大脑上由 python -m jarvis pair <设备名> 生成，只从标准输出出来一次（用重定向存进文件，不上屏）；运行目录里的 devices.json（0600）只记名字、时间和令牌的 SHA-256，比较用恒定时间。python -m jarvis unpair <设备名> 撤销一个设备，不用重启；python -m jarvis devices 只列名字和时间。回环上的请求照旧。管插件凭据、语言、Codex 额度重置和余额记录的六条路由另外还检查本地令牌，设备令牌打不开它们。没有 shell 的设备（手机）改用一次性配对码（ADR 0196），大脑上有四条路由。POST /inherent/devices/pairing，正文 {"name": "<设备名>"}，回 200 {"device", "code", "expires_at_ms", "brain"}，主人的屏幕把 code 和 brain 排成二维码。code 是 32 个随机字节的 URL-safe 文本，十分钟内有效、只能认领一次；再铸一个就让没用掉的旧码作废，同时最多一个；大脑只在内存里存它的 SHA-256，不落盘，重启后全部作废。brain 是设备该拨的基础 URL（http://<主机>:<端口>），只列过得了 Host 检查的：既在 runtime.listen_addresses 又在 runtime.listen_hosts 里的 IPv4 地址排前面，再是 listen_hosts 里的名字；只在 listen_addresses 里的地址会被 Host 检查拒掉，IPv6 字面量在第一个冒号处被截断，都不列。名字不合法回 400，名字已配对回 409，大脑没有 listen_addresses 回 409 {"detail": "this Jarvis does not listen beyond this machine"}，有地址却没有一个过得了 Host 检查也回 409。设备拿码 POST /inherent/devices/claim，正文 {"code": "…"}，回 200 {"device", "token"}，令牌和 pair 生成的一样；码认领成功即作废。错的、用过的、过期的码，以及铸码后这个名字又被别的办法配上的（码同时作废），一律同一个 401 {"detail": "invalid pairing code"}，摘要用恒定时间比较。这是除存活探测外唯一不带令牌就能打的路由，只开 POST，回环和非回环的对端都行（Host 检查照旧），正文超过 1 KiB 回 413；大脑没有 listen_addresses 时它也要本地令牌。GET /inherent/devices 回 {"devices": [{"name", "created_at"}]}，不含令牌和哈希；DELETE /inherent/devices/{name} 回 200 {"unpaired": name}，没配对回 404，立即生效。铸码、列出和撤销的对端要求和别的路由一样：回环上的本地令牌，或任何一个已配对设备的令牌。命令行的 pair、unpair、devices 照旧。

文本，不超过 8 MiB：终端先发 hello（能跑的工具名），大脑回 ready；之后大脑发 call（编号、工具名、参数、已解析的目标），终端按编号回 result，成功带一个 JSON 对象 output，失败带 code 和 message。结果只当数据读，大脑不执行其中任何东西；截图是 base64 的 PNG，不超过 4 MiB，大脑验过是 PNG 才存下并交给视觉模型。终端的 hello 里还有 timesink_read、git_read 和 claude_read，参数是读取函数名和它的 JSON 参数（时间用带偏移的 ISO 文本），成功时 output 是 {"result": …}，读取函数自己的拒绝带它原来的 code 和 message。终端可以再发 event（事件编号 32 voice，表示大脑能不能给它合成。声明了语音的终端多一类帧：大脑发 row（大脑日志的行号 id、event_uid、event_type、schema_version、ts_epoch_ms、payload，类型只限 surface.response_open|chunk|emitted 和 response.cancelled|failed）；终端发 tts 请求（会话编号 base64，提供商的一个音频块就是一帧，不拆不并，逐字时间、timing_text 和段结束事件的用量原样带上，最后以 end 或 failed 收尾；每个终端最多同时 8 个会话，链路断开大脑中止它的全部会话。声明了语音的终端发的 event 白名单再加 surface.playback_started、surface.playback_segment_prepared、surface.playback_alignment、surface.playback_checkpoint、surface.playback_completed、surface.playback_interrupted、surface.playback_failed、surface.playback_lane_isolated、surface.speech_dropped 和 tts.usage_observed，这些帧可另带 schema_version、source_event_id（要指向大脑日志里已有的行）和 correlation；没声明语音的终端发它们一律拒收。大脑收听终端时（ready 带 listen: true，ADR 0172），声明了语音的终端再多两类帧：终端发 ask（op、args；带不超过 64 字符的 id   • scripts/claude_hook.py 把令牌发给 127.0.0.1:8006 上正在听的进程，再把对方的回答交给 Claude Code，当作权限决定。
  • 安装版的 App 启动时也先带着令牌问 8006：对方答得上来，就当它是自己的后台，不再另起一个。
  • 主人在终端登录远程 MCP 服务（python -m jarvis mcp-login）时，这个命令在 127.0.0.1:8789 上临时听浏览器的回调，登录完就关；授权走 PKCE，回调只绑 127.0.0.1，并校验 state。机器上没有桌面（Linux 没有 DISPLAY）或加了 --no-browser 时，命令只打印授权网址，不打开任何浏览器。没有浏览器的大脑（树莓派）这样登录（ADR 0170）：在 Mac 上 ssh -L 8789:127.0.0.1:8789 allen@jarvis，在大脑上跑 python -m jarvis mcp-login <服务名>，把打印出的网址贴进 Mac 的浏览器；授权后浏览器跳回的 127.0.0.1:8789 经隧道到大脑上的那个命令，令牌写在大脑的 mcp/，Mac 的磁盘上没有。Gmail 不走这条：它的登录命令是 Google 那个本机服务自己的 headless-login.js（login_args，ADR 0055），本来就是打印网址、把授权后页面上的 JSON 粘回终端，所以在大脑上跑 mcp-login gmail、在 Mac 的浏览器里授权、把 JSON 粘回 ssh 终端即可，令牌加密存在大脑上它自己的目录；这个服务要先装在大脑上（~/Projects/external/gemini-workspace，需要 node）。
  • keeper.sock 和 codex.sock 不认证，靠运行目录（keeper.sock 挪进临时目录时是那个文件夹）的 0700 挡住别的账户（第 6 章）。
未满足本机端口对这台 Mac 上的每个账户都开放，另一个账户的进程可以先占住 8006，收下 hook 和安装版 App 交过来的令牌，并替主人回答 Claude Code 的权限请求。ADR 0090 要求本机接口搬进运行目录里（0700）的 unix socket，像 codex.sock 那样。安装版和开发版现在共用 ~/.jarvis 和 8006（改18）。

3. 状态脊柱

Jarvis 的状态有两类：事件日志记下发生过什么，memory.db 记下说过什么。投影从事件日志折出来，是 Jarvis 对当下的理解。两者都在运行目录里，都是这台 Mac 上的 SQLite 文件。

事件日志

  • 只追加。events 表上的触发器拒绝一切 UPDATE 和 DELETE。更正、撤销、取代都靠追加新事件，历史始终完整。
  • 每条事件是带出处的说法，不是事实本身：它记下谁在什么时候报告了什么。
  • 清单在代码里。登记过的事件类型在 jarvis/state/event_log.py 的 _REGISTRY_ENTRIES；没登记的类型写不进去。这里不抄清单。
  • 类型的含义只加不改。要改一个事件的意思，就换一个新名字；老名字照旧能读。
  • payload 有界。截图、录音、终端输出这类大块内容存成文件，事件里只放引用和摘要。
  • 一个运行目录一条日志谱系，身份记在 event_log_metadata.log_epoch（ADR 0014）。

投影

投影只能从事件折出来，模型、工具和界面都不能直接改它。现在在用的投影：待确认的卡片、待填的卡片（ADR 0066）、还没结束的动作，和一块状态板（最近几轮、观察到的仓库和提交、电源变化）。每次决策读的是当时折好的快照；它只折上一次读到的事件之后新写的，结果和从头折完全一样（ADR 0164）。

4. 动手的规矩

一轮怎么走

  1. 输入。一句语音、一段文字、一张卡片的答案或一个按钮。
  2. Tier 0。先对一张封闭的全句正则表（config/tier0_patterns.yaml）。命中就直接调那一行指定的工具，用语言表里的话回答，不调模型。每一行的工具必须是 regex_router 能用的，回答里不许出现「完成了」一类的词。在它之前还有一步：整句只是要助手再说一遍（「什么」「再说一遍」「没听清」，what? / pardon / say that again 这类），而之前有说出口的回答时，把最近那个回答的语音部分原样再说一遍，也不调模型。
  3. Jev（ADR 0122，realtime.surrogate_route，出厂关）。Tier 0 没命中、而且这一项打开时，问 TypeSafe 的 Jev 一个选择题：主人要的是 Tier 0 里哪一个不需要参数的即时功能（时间、日期、剪贴板、屏幕、开始或结束挂机、念便签，或者再说一遍），还是都不是。置信度不低于 min_confidence（0.95）且选的不是「都不是」，就按 Tier 0 命中的同一条路径执行；其余情况（低于门槛、都不是、超过 timeout_ms（400）、HTTP 出错、没有 key、答案读不懂）都当作没问，交给模型。打开 parallel（出厂开）时，主人说的话走 spoken_streaming 的那一轮不等 Jev：模型的请求立刻发出，它的第一个输出要等 Jev 答了（最多 timeout_ms）才能出声或调工具；Jev 的选择要执行时，这个请求被悄悄停掉，改走 Tier 0。其余路径先问 Jev。每次调用记成一条 route.surrogate_decided 事件。
  4. 模型的工具循环。没命中就把请求发给模型（组成见第 5 章）。一轮里带工具的请求最多 llm.max_tool_iterations 次（不写是 5，出厂配置是 40，ADR 0060）；Allen 开口说的那一轮改用 llm.max_tool_iterations_voice（出厂配置是 8，不写则同上，ADR 0178）。到顶后再发一次不带工具的请求来收尾，语音轮的收尾沿用本轮的 spoken/written 回复格式。
  5. 每个工具调用都先变成一个动作请求，过前置闸门，通过了才执行；闸门的每次判断和动作的每一步都记成事件。

风险等级与调用者

等级含义例子
L0读、观察看时间、读剪贴板、列备忘、读文件、等 worker 的结果、只读的插件工具

前置闸门

每个动作请求都过四项检查，四项都跑完再下结论，结果记成 gate.evaluated：

  1. 这个调用者能用这个工具；
  2. 需要目标的工具，目标来自可信的解析，不能是模型编出来的 ID；
  3. 风险不超过上限；
  4. 到了确认线的动作，带着有效的授权。授权在主人接受确认卡时生成，限定工具和目标，会过期，只能用一次，从不存起来复用（ADR 0012）。

确认卡（ADR 0062）

  • 要确认的动作变成一张卡片，卡片不过期；一次只等一张，新的请求替换旧的。
  • 主人自己开始的对话还在、对话区开着时，卡片出现在对话区里她最新一句的下面，她留在外面，刘海里不出；卡片等着时对话区不收起。对话区没开时卡片从刘海里垂下来（ADR 0131）。
  • 按钮是正路。接受时可以当场改已有的字符串参数，改过的参数重新冻结成一张新卡再接受。
  • 问出之后，confirmation.ttl_ms（默认 10 分钟）内的第一句话也可以用是和否来回答。Jarvis 不分辨是谁说的（ADR 0090）。

不变量

I1 没有事件，就没有持久的状态变化。
I2 事件写下就不能改，只能追加更正。
I3 投影只读，只能由事件重建。
I4 没有生效的策略，就不动手。
I5 调用者只能用策略给它的工具。
I6 真实对象的 ID 不能编。
I7 高风险的动作必须确认。
I12 记忆不能证明当前状态。
I8 到 I11 随审核链退役（ADR 0019），编号保留。

交给 worker（ADR 0019）

后台的 worker 是 Codex app-server 的线程，模型用四个工具驱动它：派活、等结果、补一句话、关掉。派活是 L3，要确认；worker 只能在 tools.workers.roots 列出的目录里干活。worker 的最终消息原样交给模型和主人，Jarvis 不判定它做没做成。Agents 窗口里的会话是另一回事，见第 8 章。

5. 什么离开这台 Mac

  • 窗口决定压缩（ADR 0134）。recent_records 大于 0 时，上面三个条件不再看：窗口放不下的记录一出现，就在后台折进摘要（上一段摘要加这些记录），一次只跑一个。折叠失败或被拒，保留旧摘要，等下一条新记录再试。
  • 按天摘要的历史（ADR 0149）。session.context 设成 day_summaries 时，历史改为：一条开头消息，列出最近三天（早于边界日）的日摘要，最早的在前；一行说明边界日（有日摘要的最新一天的后一天）从零点起每一句话都在下面；再是边界日起的每一句，渲染方式不变。这些句子的文字超过 session.context_raw_max_chars（40000）时，最早的按 50 句一块隐藏，前面加一行说明有几句、用 recall 或搜索工具去找。此时 recent_records 不起作用，滚动摘要既不发送也不再写，压缩和窗口折叠都不运行；还没有任何日摘要时，这一轮仍按上面的滚动历史。历史的开头每天只变一次，服务商的缓存整天接得上。
  • 压缩本身也是一次模型调用，发出的是要折叠的那些记录；一次折叠要读的记录太长时分段，每段接着上一段写出的摘要往下写。
  • history_since 之前的记录，以及 recent_records 窗口之外的记录，留在 memory.db，原话要用时通过搜索工具取回，不进每一轮的请求（窗口之外的内容进摘要）。窗口的起点每 N 句才往后挪一次，其间历史的开头不变，服务商的缓存才接得上。

要护住的

装上的东西被换掉。App 签名并公证；SenseVoice 和 VAD 模型下载后核对 SHA-256没有自动更新，修复送不到装好的人手里（包4）。本地 Whisper 的权重（mlx-community）由它自己的库第一次用时下载，Hue 插件由 uvx 从 PyPI 取 huemcp==0.1.0，都不核对哈希。插件没有签名，也不声明自己要什么权限。agent 宿主每小时替主人升级 Claude Code，不先问（第 8 章）

本机的其他入口

下面这些现在只靠「别的账户进不了运行目录」或「默认关」护着。公开版之前每一条都要重新看过。

  • ~/.jarvis/agents/keeper.sock 和 ~/.jarvis/codex.sock 不认证：连得上的进程可以让 keeper 以主人身份启动任意命令，或者驱动 Codex。
  • 终端上的 brain-token 是明文的 0600 文件：拿到它就等于拿到这台终端，直到大脑上 unpair 它。
  • agent 宿主的钥匙和后台的令牌都能打开宿主的 /term，拿到主人的登录 shell，所以拿到其中任何一把就等于拿到这个账户（ADR 0095）。
  • 用量页打开后，用 Claude Code 和 Codex 存在这台 Mac 上的登录、以它们命令行的 User-Agent 去问用量；在页面上确认一次，会花掉一次 Codex 的限额重置（第 8 章）。

key 放在哪

  • 模型服务商的 key 存在主人的登录钥匙串里：每个运行目录一项（服务名 Jarvis，账户是运行目录的路径），内容是 {环境变量名: key} 的 JSON。写入走 security -i 的标准输入，key 不出现在任何进程的参数里。用临时运行目录跑的测试后台读不到主人的 key。
  • ~/.jarvis/env 是主人自己写的明文 名字=值 文件，只补钥匙串和进程环境里都没有的变量。macOS 上代码只读它、不写它，也不改它的权限；护住它的只有运行目录的 0700。
  • Linux（跑后台的那台机器，ADR 0170）没有钥匙串，key 就是这个 env 文件里的行。保存时把整个文件写到旁边再改名换上，权限 0600，别的行和注释原样保留；读取和保存都不调 security；「抹掉全部数据」连这个文件一起删。
  • 安装版里 Agents 窗口的 Claude 会话用的 Anthropic key 单独存一项（账户是运行目录里 agents 文件夹的路径），同样经 security -i 写入。后台不读这一项；宿主只把它放进自己开的 Claude 会话的环境里（ADR 0094）。
  • 插件凭据和 MCP 的登录令牌现在是 0600 的明文 JSON（改17）。
  • 「抹掉全部数据」会删掉这两项钥匙串（第 9 章）。

花费

  • 每次调模型都记一条 cost.recorded，按 data/pricing.json 的价目表折成钱。
  • 不设硬上限：花费不会让任何模型停下（ADR 0185）。当天（本机时区）已记的美元总额第一次超过 spend_cap.daily_usd（默认 1.00）时，刷一次提示卡，每天最多一次，job mail 开不开都会出；语音按字计费、Jev 有自己的日志，都不在这个总额里。按秒计费的实时语音 gpt-live-1 在价目表里没有价格，记不上账。
  • 首次设置测 OpenAI key：先列一次模型（不花钱），再真的调一次对话模型，最多 200 个输出 token，发出去的提示里带着主人和助手的名字（改6）；最后只查模型列表里有没有后台要用的模型和 gpt-live-1。测 MiniMax key 会合成一个词的语音，测 Tavily key 会花掉一次搜索。
  • 后台每次启动都重测已存的 key：OpenAI 只列模型，不花 token；MiniMax 合成一个词，按字计费。
  • 安装版的 Agents 窗口存 Anthropic key 之前只列一次模型，不花钱。
  • 每一轮都带着逐字的历史，历史越长，每一轮越贵；压缩的门槛见第 5 章。

读对方的状态

  • Claude Code 的会话（ADR 0046）：跑 claude agents --json 拿名单和实时状态，读会话的 state.json 和对话记录的末尾。不往 Claude Code 里装东西，不写它的文件。默认关（observer.claude_sessions.enabled）；hook 送来的标记不受这个开关影响。
  • 回后台会话一句话：打开上一条之后，主人可以在刘海里回一个空闲的后台 Claude 会话。后台在一个看不见的终端里跑 claude attach，把这一行打进去、回车、再断开；这个终端的环境里去掉了 ANTHROPIC_API_KEY，不走 API 计费。
  • Codex 的会话记录 ~/.codex/sessions：只有打开 daily_report.codex_sessions 时，日报才读它并发给模型。默认关。
  • Codex 会话的标题：刘海和 Agents 窗口读 ~/.codex/session_index.jsonl（设了 CODEX_HOME 就读那里的），最多十秒一次。
  • Ghostty：刘海上有 Claude 会话时，每 0.4 秒用 AppleScript 读一次 Ghostty 最前面那个标签页的标题，用来判断主人是不是正看着那个会话；点「打开」时也用 AppleScript 让 Ghostty 切过去或者新开一个标签页。
  • 主人的全名：首次设置用 id -F 读这个账户的全名，取第一个词作名字的默认值。

Agents 窗口（ADR 0073）

  • agent 宿主通过 Claude Agent SDK 驱动 Claude Code，用的是这台 Mac 上主人自己装的 claude 和它的登录；找不到时退回 SDK 自带的可执行文件。Codex 通过 codex app-server，也就是 Codex 自己的桌面 App 用的那套 JSON-RPC 接口。
  • 新会话默认开一个自己的 git worktree；删会话时只在 git 允许的情况下删掉它的 worktree，主人再按一次确认强删时，没提交的改动先存成仓库里 refs/startrail/trash/ 下的一个提交。对话从 agent 自己的记录里读回来；未读、搁置和归档的标记由后台保存（ADR 0069）。
  • 窗口能列出这台 Mac 上它还没有的 Claude Code 和 Codex 会话（SDK 的 listSessions、app-server 的 thread/list），主人选一个，就用同一个 id 在窗口里接着跑；两分钟内还动过的可能还在别处开着，要再按一次（ADR 0096）。
  • 窗口能看会话连着的 MCP 服务器，并替主人回答它们要填的表和要打开的网页。关掉一个 Claude Code 的 MCP 服务器，是 Claude Code 自己记在这个文件夹的配置里，终端里在这个文件夹开的 Claude Code 也一样关着；Codex 的服务器在这里只能重新读配置和登录，开关要改它自己的 config.toml。Claude Code 的服务器要登录时也在窗口里登：会话自己的 Claude Code 给出登录页，窗口在浏览器里打开，主人登好后由它连上。Codex 要主人验证身份的请求仍然拒绝。
  • 主人能在会话旁边另问一句，不打断它正在跑的那一轮，这一问一答也不进对话：Claude Code 用它自己 /btw 的那一问；Codex 学它自己的 /side，从这段对话开一个不存盘、只读、不问审批的分叉，答完就放掉。
  • 主人能改自己说过的一句再发：正在跑的那一轮先停下，对话回到这一句之前，再发新的话。改出的是一个新会话，留着原来的标题、在列表里的位置和标记；原来的归档成上一版，不进列表，在这一句下面翻得到，在它里面写一句它就换回来。Claude 会话的文件按 Claude Code 自己的检查点一起退回，Codex 只退对话；翻版本不动文件。
  • 主人给消息加的表情不叫醒 agent：宿主按消息记下，主人发的下一句前面带一行 [Reactions: …] 一起过去，每个只带一次。
  • Claude 会话清空上下文（/clear）后，Claude Code 换一个新的 session id 接着写。窗口里的一行按先后记下每个 id，在最后一个里继续，读回时依次读全部记录，并在清空处标一行（ADR 0088）。
  • 一键落地把会话的改动落到仓库的默认分支（origin 的 HEAD 指的那个，没有就 main，再没有就 master），两种走法：合入是提交、快进合进默认分支、重启、主人允许后推默认分支、删掉会话的 worktree；开 PR 是提交、主人允许后推会话的分支并用 gh 开 PR，不重启，worktree 留着。没装 gh 时停在推好的分支和远端给的开 PR 链接。门禁、重启命令和默认走法按仓库在设置里配；没配时 Jarvis 仓库用 docs/git-guide.md 的门禁和重启，别的仓库没有。Jarvis 仓库默认合入；别的仓库两条都能走又没配过时，第一次落地先问主人走哪条，答案记进这个仓库的设置，之后不再问（没答就开始的按开 PR）；会话就在默认分支上只能合入，不在自己 worktree 里的别的分支只能开 PR（ADR 0097）。
  • 会话可以属于一个项目（ADR 0118）。项目是 agents/projects/ 下的一个文件夹：设置（名字、目标、最多 16000 字的项目说明、默认文件夹、agent、模型、力度和模式）、以 MEMORY.md 为索引的记忆文件夹和共享文件夹。会话在项目里开，或者之后移进去、移出来。它的 agent 每次启动都拿到项目说明和截到 200 行、25000 字的记忆索引（Claude 接在 Claude Code 自己的系统提示后面，Codex 作为 developer instructions），并能读写记忆和共享文件夹；正在跑的进程到下次启动才看到改过的说明和记忆。项目里的会话按等你、在跑、落地中、待审、闲着、完成分组，读的时候现算，7 天没动的算完成。
  • 项目可以开一个协调者（ADR 0119，新项目默认开，Sonnet、低力度，按项目换）：宿主替项目跑的一个 Claude 会话，用它自己的提示词，不读主人的 Claude Code 设置、CLAUDE.md 和 hook，能读文件，只能写项目的记忆和共享文件夹，不能跑命令。它的普通文字谁也看不到，只有工具调用到主人面前：在项目的消息流里发言、改自己的发言、带一份简报开会话、给会话捎话、替主人起草一句话、列出和读项目的会话。宿主只在三种时候叫醒它：主人在消息流里说话，主人在项目的会话里说话，项目的会话做完一轮或出错；1.5 秒内的事并成一条，不定时叫。上一个的上下文过了 10 万 token 或闲了一小时，就换一个新的，交给它项目说明、记忆索引、会话列表和消息流最近 30 条。
  • 协调者写给会话的话第一行是 [From: coordinator]，窗口里记成协调者说的，不是主人。它要转述主人的话只能给出那条消息的 id，由宿主把原文一字不改地附在后面；项目会话的提示里写明只有这部分算主人的话。草稿在消息流里是一张卡，主人按一下就作为主人自己的话发到那个会话，不叫醒协调者。项目的会话等主人批准时，宿主自己在消息流里发一行，等完了把它划掉并写上已处理；这不经过模型，也不叫醒协调者。
  • 宿主在启动时和之后每小时替主人跑一次 claude update，升级主人自己的 Claude Code。
  • 开发版里这些会话用这台 Mac 上 Claude Code 自己的登录。安装版里窗口开的每个 claude 只拿主人自己的 Anthropic key，或 Amazon Bedrock、Google Vertex 的设置，放在那个进程的环境里；都没有就不开 Claude 会话，并说缺什么。Claude Code 自己的登录不读、不改、不限制：宿主的环境、它开的终端和 claude update 都拿不到 key（ADR 0094）。
  • 在 App 里运行 Claude Code 要先同意 Anthropic 的商业条款。Allen 确认之前，安装版不带 Claude Code，也不开这个窗口（改19，定6）。
  • 窗口自己的字跟着 Jarvis 的语言（settings.yaml 里的 language，桌面设置里的开关）：是 en 就全英文，其他情况或后台不应答时是中文。agent 自己的回答和主人写的话不翻译；开着的窗口在下一次打开时换语言（ADR 0109）。

用量页（ADR 0018）

默认关（observer.usage.enabled），因为它要读别的程序的登录。打开后每 5 分钟问一次，数字变了才记一条 usage.state_observed；存下的只有百分比、金额、时间和套餐名，不存令牌。大脑和终端分开部署时（ADR 0170），Claude 和 Codex 两行由终端按它自己配置里的 observer.usage 读这台机器的登录、把事件推给大脑，另三行由大脑用它的钥匙读；页面上的刷新只刷新大脑读的那一半，花掉 Codex 重置要本地令牌、读的是所在机器的登录，终端的伴侣上还做不到。

9. 安装、更新、卸载与数据

安装

  • 发的是一个 DMG 里的 App：Developer ID 签名、开了 hardened runtime、经过公证并装订。App 自带 Python、锁定版本的运行依赖和后台的代码（构建时编好字节码，运行时不往签名过的包里写任何东西）。
  • 只支持 Apple Silicon。最低系统版本还没设（包6）。
  • App 不在 Dock 里。第一次打开走首次设置：主人的名字、助手的名字、语言、OpenAI key、声音、系统权限和要连的服务。
  • 本地语音模型不在包里：后台发现缺了就在后台下载，核对 SHA-256，下好后自己重启一次；下好之前只能打字。
  • 大脑不走 DMG：在 Linux（x86_64 或 aarch64，uv.lock 三个平台都解了）上从仓库装，key 放在运行目录的 env（第 7 章），启动前在 settings.yaml 里写 runtime: {role: brain}。设置页的重启和抹掉全部数据在那里还不可用，它们靠 launchd 的标记（JARVIS_LAUNCHD_AGENT）重启后台。
  • 当终端用的 Mac 想开机自启：jarvis terminal-agent install --brain http://jarvis:8006（先 jarvis daemon uninstall），拆除用 jarvis terminal-agent uninstall；见进程。

运行目录

一切状态都在运行目录里：默认 ~/.jarvis，可以用 JARVIS_RUNTIME_ROOT 换。后台每次启动都把它设成 0700。

规则

  1. 安静优先。默认不打扰；主动开口要有证据和理由。
  2. 表面不拥有真相。界面只读投影、发事件，或发出经过闸门的请求；它缓存布局，不缓存任务状态。
  3. 语音不承载密集的证据。长的、要核对的内容放面板。
  4. 面板是默认的工作表面。工作状态先给面板，不先给语音。
  5. 通知要限流。只用于要紧的事或值得主人看一眼的结果。
  6. 环境动作可逆、低噪。开关灯这类动作能撤回，不制造声响。
  7. 每次开口都有来处。表面上的每一次输出都能追到一个事件或一次决策。

注意力

注意力是几条固定规则：没有打分，也不从主人的反馈里学。专注模式做出来时，写成第二个真正的模式，并先写 ADR。

求职邮件（ADR 0155，job_mail，出厂关）：事件、上下文包、裁判、投递、反馈、日志六步，裁判是唯一可换的一个函数，现在是主人定的规则表：回执只进账本，拒信出卡片，其他求职邮件出卡片加提示音，面试和 offer 出卡片，并说一句固定的话（只在安静档为 off、没静音、不在对话里、十分钟内没说过时说，在提醒产生时一次定下，之后不补说）；收到时已超过 48 小时的只进账本。所有提醒受安静档管：quiet 去掉提示音，no-pop 和 dnd 什么都不出、提醒留着，等过半分钟的两条以上、或九十秒内连来的三条，合成一条摘要（每行是一个公司的一个邮件线程：取最重要的类型、最长的岗位、往来封数，有读出的面试时间就把它作为这一行的要点；标题在全是同一家公司、同一类邮件时写「某公司 面试有 N 封新邮件」，否则写「最近两天有 N 封求职邮件，其中 X 封面试」；最多带提示音，从不开口，带一个打开求职账本的入口，和一行「合适吗」，选一个级别或点「对」就对摘要里的每封邮件各记一条反馈，所示级别是摘要的级别；已在库里的待办提醒读取时同样合并，不迁移、不删除）；九十秒内的第三条起不再开口，单独一封面试或 offer 仍照旧开口。几条本地规则在 Jev 分类之后按发件人和主题再分一次：LinkedIn 社交动态和个人主页动态（「你出现在 N 次搜索中」「你的主页被浏览了 N 次」）算不是求职邮件；求职网站的账号或系统通知（如「CGI - User Information」）类型为账号通知，只进账本，不提醒；LinkedIn 的职位提醒汇总邮件是主人定的规则（2026-10-04）：永不出卡片、提示音或语音，只进账本（job_mail.linkedin_alerts 默认 ledger_only，求职账本页上有一行说明）。job_mail.exclude_domains（默认 [linkedin.com]，主人 2026-10-06 定）里的发件域名的邮件整封挡在求职邮件之外：读完标题就由本地规则挡下，不问 Jev，不进账本、不提醒，出现在被挡下的列表里，主人的标记仍能把它拉回来；已在账本里的旧记录启动时隐藏、不删除；设为 [] 只停止挡新邮件，已隐藏的仍隐藏（ADR 0171）；唯一的例外是 LinkedIn 的「your application was sent to X」（Easy Apply 投递确认）：它是一次投递，不挡，按普通邮件分类，公司取主题里的 X（ADR 0177）。公司取发件域名所属的机构而不取人名，正文里「X's QA」这样的所有格加岗位词不算公司名，「applying to X's 岗位 position」能读出岗位，岗位只取主题或正文里读得出的，不存「job」这类泛词；启动时按已存的发件人、域名和主题把旧记录修一遍，不读 Gmail，也读决定快照里存的正文开头（ADR 0158、0159、0168）。每个决定连同裁判看到的完整上下文包记进 attention_log，主人的反应跟着追加；日志不参与决定，只供回放别的裁判。读不到邮件（连续三次或两小时）时出一条邮件通道的提醒，十二小时最多一次，恢复时不出声。job_mail.interview_reminders（主人 2026-10-06 定）：每个申请的下一个面试时间，由后台自己设两条提醒（前一晚 20:00 和开始前 30 分钟，写法同 ADR 0179 的提醒事件）并在他的 Outlook 日历里写一条带 30 分钟提醒的面试，不问他；时间变了就取消旧的、设新的、改那一条日历，申请被拒或被隐藏就全部撤掉；Jobs 页的面试行说明已设了什么，并有一个「取消提醒」。Outlook 这一条是在 Pi 大脑和 iPhone 推送做好之前的权宜之计（ADR 0186）。

现况（ADR 0161，moment，出厂开）：产生、开口前和提供提醒时才读一次 TimeSink（只读，不复制，不调模型）。主人在通话或会议里（看前台窗口：Zoom、Meet、Teams、FaceTime、Webex、腾讯会议；Discord 语音和共享屏幕认不出来，屏幕共享恒为 unknown；后台窗口超过 90 秒也认不出），或者空闲、锁屏、休眠时，所有卡片和提示音都压住、一句话也不说，提醒留在待办里不算「已显示」，结束或回来后照 ADR 0158 的规则合成一条摘要（只有一条就是一张卡）；读不到、过期或不确定时什么都不压，和以前一样；扬声器上不出声的规则不变。客户端自己生成的卡片（ADR 0163：代理做完或停了的弹窗、做完却在问主人的、要主人点头或回答的、夜里屏幕亮起的卡片、第二天早上的卡片）也遵守同一条规则：守护进程把 hold（call、away 或空，规则就是上面那一条，读到才算）放进 GET /inherent/notices 的每次回答，没开求职邮件时放在 GET /inherent/moment（没开现况时 404）；有 hold 时这些卡片不出现、不响，攒在待办里，结束后一张就是一张、多张合成一条「你不在时有 N 件事」，一件不丢，要回答的请求不会被自动回答也不会过期；主人自己从刘海的列表点开的卡片不受影响，睡前卡（他自己开始挂机）和确认卡、补问卡从不被压；缺字段（旧守护进程）、接口 404、守护进程连续三次没回，什么都不压，通话超过 3 小时按不确定处理；卡片快照记 held_by 和 held_s。每个决定的快照里存一份由代码拼出的「现况」小文档（不超过 400 字，英文，因为是给模型看的：Now、Today so far、Your situation，后者暂空；九个字段各有开关，在 moment.fields，启动时检查），只含 App 名和网站域名，从不含窗口标题或网址。

亮一下（ADR 0187）：最轻的一档找到主人的方式，是刘海右边「轮到你」那一组多一个琥珀点，不出卡片、不响、不开口；点和别的新到的事一样跳一下、闪两圈，然后不动，它在那一组的列表里排在会话之后，一行是标题、一句话和多久以前，点一行打开它的地方并算看过，点叉清掉，两者之前它一直在，重启也在。它是标记不是卡片：quiet、no-pop 和通话、离开时照样亮，只有 dnd 先攒着，出来后仍是亮一下，从不并进摘要。它走求职邮件的提醒行（级别 glow），所以要 job_mail 开着；现在还没有哪件事被判为这一档。

别的主动卡片也问「合适吗」（ADR 0160）：代理做完或停了的名字弹窗、做完却在问主人的、要主人点头或回答的卡片、从 no-pop/dnd 出来时的「你不在时有 N 件事」、夜里屏幕亮起的卡片和第二天早上的卡片，都带和求职邮件同一个折起来的「合适吗」（对，或五个级别之一，卡片自己的级别标出）；弹窗、摘要和早上的卡片点一下就关，要回答的卡片和夜里的卡片点一下只说声谢谢，卡片还在。卡片出现时客户端把它的快照（种类、标题、数量、工具名，和所示级别：提示音可以响时是「卡片带声」，否则是「卡片」）报给守护进程，主人的反应（对、级别、用了卡片自己的按钮、关掉）随后报上去；不报代理写的话、命令或路径。主人正在做的事里冒出来的卡片（确认卡、补问卡、他自己开始挂机的睡前卡）和他自己点开的页面（早报块、用量、邮件）不问。

不请自来的声音只在私密输出上响（ADR 0156）：主人没问就出的声音（求职邮件那句话、卡片出现时的提示音，对代理通知也一样）只在默认输出是耳机一类（蓝牙、耳机孔、名字像耳机）时才响；内置扬声器、显示器、USB 音箱、虚拟设备、探测失败一律不算，卡片照出但没有声音。

安静档（ADR 0153）：守护进程保存一个档位，off、quiet、no-pop、dnd，逐级叠加，重启后还在，从不自己结束；表面只读它，不存副本。quiet：她不主动开口，所有提示音关掉（通知提示音和十分钟后的再提醒），卡片和名字照常出现但没有声音；主人对她说话她照常用声音回答。no-pop：再加上不弹卡片和名字，刘海右边的 agent 星星和亮一下的点照常更新，Claude Code 的权限请求不再停在刘海上、立即交给 Claude Code 自己的对话框。dnd：再加上对外部的一切事都没有可见反应，全部先攒着，刘海旁的星星和标记也停在进入时的样子；从 no-pop 或 dnd 出来时攒下的一次给出：两个以上会话有动静时是一张卡「你不在时有 N 件事」，一行一个会话，要回答的在前，其次出错，最后做完，点一行打开那个会话（要回答的点开就是它的卡片），只有一件事时就是它平常的样子。主人自己设的提醒和闹钟任何一档都照响，通话和离开时也不压：提醒由模型的 set_reminder 工具设（绝对时间带时区偏移，备忘录不会提醒），存在事件日志里，守护进程每 15 秒查一次，到点说一句「提醒：……」并出一张不带提示音的卡片，外放也说（通话中、静音、对话中不说，这时卡片带提示音；守护进程停过或 Mac 睡过而晚了的，补响并说晚了多久，晚了超过 12 小时的只出卡片）；不并进求职摘要（ADR 0179）。切换：POST /inherent/controls {"quiet": 档位}、整句固定短语（安静一点、别弹了、勿扰、恢复正常，英文同义，不经过模型，用一句固定的话回答，整句才算，单说「安静」「安静一下」仍只是让她停下）、她的右键菜单；有档位时刘海里有一个小图标。

刘海上的卡片规则（ADR 0153）：项目对话（RC 在 ~/Projects 起的会话）里的 Claude 会话不进他的队列，它们的权限请求也不停在刘海上；他在 Claude（桌面版在前台，或前台终端是某个 Claude Code 会话）时不出名字和卡片、也没有声音，只有星星标记，停着的权限请求在他离开 Claude 后才出来；卡片可以用 Esc、卡上的叉、横向轻扫、点屏幕别处放下，放下不是先放着、也不会十分钟后再来提醒，它仍在他的待办列表里；同一个会话同一句话只出一张卡。
