Jarvis

spec v2 2026-09-29 起 只写公开版必须满足的事

这份 spec 写 Jarvis 的公开版必须满足什么：给谁用，由哪些进程组成，状态怎么存，什么时候能动手，什么会离开这台 Mac，防什么，钱怎么花，怎么接 Claude Code 和 Codex，怎么装、更新和卸，什么时候开口。为什么这样定写在 ADR 里。单个功能的接口、字段和界面细节由定义它的代码和测试负责，这里只收别的程序要依赖的格式，和主人要知道什么离开了 Mac 时需要的清单（ADR 0089）。

怎么引用。用锚点，例如 docs/spec.html#egress，不用 § 编号。代码、配置和测试里在 ADR 0089 之前写下的 § 编号指向已归档的 docs/spec-v1.html，那份只是背景。

两种标记。未满足是 ADR 已经定下、代码还没做到的规则。「现在还没有」说的是现状：要改它，先写 ADR。缺口后面的「改N」「包N」是《Jarvis 发布清单》的条目编号，进度记在那里。

用词。「Jarvis」是产品现在的名字，以后可以改（ADR 0091）。「主人」是装它的那个 macOS 账户的人（ADR 0090）。「助手」是主人起了名字的那个它。

1. 定位与主人

一句话

给同时用 Claude Code 和 Codex 的 Mac 开发者的刘海伙伴。替主人盯着所有 agent，记住主人的一天，只在值得的时候开口。下载就能用，用主人自己的一把 key。
它是它不是
一人一份。每个 macOS 账户一个主人，主人的名字在首次设置时定下（ADR 0090）。又一个干活的 agent。写代码、操作电脑交给 Claude Code 和 Codex。
agent 的总管。派活、盯进度、收结果，审批不用切窗口。多人协作或团队工具。一个安装只认一个主人。
本地优先。状态都在这台 Mac 的运行目录里。Jarvis 没有自己的服务器，发出的请求只去主人配置的服务商、主人连上的服务，或对话里要打开的网址（见第 5 章）。云服务。不中转主人的数据，也不转售模型额度。
一把 key。默认打开的功能只用主人自己的一把 OpenAI key（ADR 0092）。智能家居中枢。树莓派、跨设备联邦和房间屏幕不在这一版里；Hue 这类设备走插件（ADR 0079）。

宪法

六条原则约束下面所有章节。改其中任何一条都要先写 ADR。

C1. 一台 Mac 一个主人（ADR 0090）。一个安装只服务它所在 macOS 账户的那个人：记忆、key、确认和注意力都是这个人的。它可以尽量贴合主人的项目、习惯和说话方式，但代码里不写死任何具体的人，陌生人第一次打开也要看得懂。同一台 Mac 上的两个人是两个账户、两份安装，只共享硬件。Jarvis 不分辨声音：主人的 Mac 旁边说话的人，都被当成主人。
未满足模型读得到的文字里还写着 Allen：浏览器护栏的拒绝语、Agents 窗口回给 Claude 的拒绝语，以及日报、工作状态和压缩的提示词（改2）。存下来的记录用 allen 标记主人说的话；这个存储值可以等数据迁移再改，但后三种提示词把它原样摆在模型面前，要先换成中性的说法。本机接口认的是固定端口，不是账户（见第 2 章）。
C2. 状态才是本体。身份不在模型、提示词、工具或语音管线里，而在持续维护的状态里：只追加的事件日志，和从它折出来的投影（第 3 章）。换模型、改提示词、加工具都不动它。
C3. 少让主人重复解释。核心价值是主人不用重新装载上下文：哪个 agent 在干什么，昨天做到哪，哪些事没收尾，下一步先做什么。
C4. 总管，不是干活的。Jarvis 派活、盯进度、收结果、整理状态；写代码和改文件交给 Claude Code 和 Codex。主模型没有终端、打补丁或写文件的工具。worker 的最终消息原样转给主人，Jarvis 不替它判定做没做成（ADR 0019）。
C5. 权限越高，越要受约束、留痕迹。每个动作都过风险等级、确认和闸门（第 4 章），并留下事件。工具返回成功、agent 自报、模型自信，都不能单独算作目标达成；Jarvis 说出口的话不比它看到的更肯定。
C6. 表面可换，连续性不断。语音、刘海、面板、通知都只是表面。换语音服务商、换界面，都不能断掉状态。

名字（ADR 0091）

名字谁定用在哪
产品名，现在是 Jarvis发布方，定义在一处；改名只改这个值和图App 包和它的权限提示、窗口、安装、第三方登录页、首次设置和设置里，凡是指这个软件的地方
助手的名字（assistant_name）主人，首次设置时起，设置里能改；没起时等于产品名它说话、被称呼、被描述在做事的地方；提示词里的 {assistant}
代码名 jarvis固定，改名时也不变指向已存数据或已给权限的标识符：Python 包、运行目录 ~/.jarvis、JARVIS_* 环境变量、LaunchAgent 标签、钥匙串服务名、bundle id。从不当作名字显示
唤醒词，现在是 “Hey Jarvis”唤醒模型（microWakeWord，ADR 0042）不跟助手的名字走；有了别的短语的检测器才变。首次设置和设置要写明用哪句唤醒
未满足桌面端有 107 行、jarvis/shared/lang.py、打包脚本和 OAuth 客户端名直接写着 Jarvis，要逐条分成产品名和助手名。标识符里还带着作者的名字（com.allen.jarvis、com.alllllenshi.jarvis）：要不要换是改3，第一次公开发布之前换只影响作者自己这一份。

Jarvis 对主人的承诺

  • 安静优先。默认不打扰，主动开口要有理由（第 10 章）。
  • 状态看得见。主人想知道的当前状态都查得到，并看得出是什么时候的。
  • 不夸大。没看到结果的事，不说成做完了。
  • 不瞒。什么会发出去、发给谁，写在第 5 章；它动过什么，事件日志里都有。

2. 系统长什么样

一台 Mac 上三个常驻进程：后台、伴侣和 agent 宿主，加上按需拉起的 keeper、Codex app-server 和 hook 脚本。它们之间只在本机说话；往外发的请求见第 5 章。进程之间的接口由说它的代码定义，不写在这里（ADR 0089）。

进程

进程做什么谁拉起、谁重启在哪听
后台（Python，python -m jarvis serve）麦克风和扬声器、本地语音模型、记忆、工具、事件日志，以及发给模型的每个请求安装版由 App 拉起，退出就重启（跑满一分钟才退出的，一秒后重启；连续崩溃时间隔翻倍，最长一分钟）；开发机上是 LaunchAgent com.allen.jarvis127.0.0.1:8006，HTTP 和 WebSocket。安装版发现 8006 被一个答不上令牌的进程占着，就换一个空闲端口
伴侣（Electron）刘海里的她、面板、Agents 窗口、首次设置和设置安装版就是 App 本身，不在 Dock 里；开发机上是 LaunchAgent com.allen.jarvis.resonance不监听
agent 宿主（Node）Agents 窗口里的 Claude Code 和 Codex 会话，工作台的终端、预览和落地（ADR 0073、0086、0087、0097）伴侣发现 8016 没人应答时拉起；伴侣或后台重启时它照常运行127.0.0.1:8016，HTTP
keeper（Node，每个 Claude Code 会话一个）替宿主抱住 Claude Code 子进程的输入输出，宿主重启后交还（ADR 0098）宿主拉起~/.jarvis/agents/keeper.sock；这个路径超过 socket 地址的上限（macOS 是 104 字节）时，在临时目录里一个只有主人能进的文件夹
Codex app-server，给 Agents 窗口宿主通过它驱动 Codex宿主拉起，走标准输入输出不监听
Codex app-server，给后台的 worker后台派给 Codex 的活（ADR 0019）；默认关（tools.workers.enabled）后台第一次派活时拉起~/.jarvis/codex.sock
hook 脚本Claude Code 和 Codex 在会话事件上运行它们，把状态和权限请求交给后台（第 8 章）Claude Code 或 Codex 每次触发时运行不监听，连后台

本机接口

  • 后台只接受 Host 头是 127.0.0.1 或 localhost 的请求，挡住把自己域名重绑到本机的网页。除了存活探测和自带每次启动令牌的 v2 路由，每个请求都要带运行目录里 plugin-access.json 的令牌。
  • agent 宿主的每个请求都要带它自己的钥匙：agents/host-key 里的 32 个随机字节，只有主人能读，宿主和伴侣谁先用到谁生成（ADR 0095）。后台的令牌也还能打开它，留给这次改动之前的伴侣。它回 Access-Control-Allow-Origin: *，不查 Host 头。
  • scripts/claude_hook.py 把令牌发给 127.0.0.1:8006 上正在听的进程，再把对方的回答交给 Claude Code，当作权限决定。
  • 安装版的 App 启动时也先带着令牌问 8006：对方答得上来，就当它是自己的后台，不再另起一个。
  • 主人在终端登录远程 MCP 服务（python -m jarvis mcp-login）时，这个命令在 127.0.0.1:8789 上临时听浏览器的回调，登录完就关；授权走 PKCE。
  • keeper.sock 和 codex.sock 不认证，靠运行目录（keeper.sock 挪进临时目录时是那个文件夹）的 0700 挡住别的账户（第 6 章）。
未满足本机端口对这台 Mac 上的每个账户都开放，另一个账户的进程可以先占住 8006，收下 hook 和安装版 App 交过来的令牌，并替主人回答 Claude Code 的权限请求。ADR 0090 要求本机接口搬进运行目录里（0700）的 unix socket，像 codex.sock 那样。安装版和开发版现在共用 ~/.jarvis 和 8006（改18）。

分层

后台的代码分六层，加上最上面的 cli 和唯一负责接线的 runtime。.importlinter 规定只能从上往下 import：cli → runtime → 中间四层（互相不 import）→ state → constitution 和 shared（什么都不 import）。lint-imports 是提交前必须过的门。

层包管什么
L1 宪法jarvis/constitutionC1 到 C6 和非目标，作为常量
L2 状态jarvis/state事件日志、投影、memory.db 和其他本地存储
L3 决策jarvis/decisionTier 0 路由、策略、闸门、每轮请求的组装、日报和工作状态的分析
L4 执行jarvis/execution工具、worker、插件和 MCP 客户端、浏览器护栏
L5 表面jarvis/surface语音、HTTP 和 WebSocket 接口、Claude Code 和 Codex 会话、屏幕和用量这类观察者
L6 部署jarvis/deployment运行目录、钥匙串、launchd、睡眠唤醒、模型下载、导出和抹掉

3. 状态脊柱

Jarvis 的状态有两类：事件日志记下发生过什么，memory.db 记下说过什么。投影从事件日志折出来，是 Jarvis 对当下的理解。两者都在运行目录里，都是这台 Mac 上的 SQLite 文件。

事件日志

  • 只追加。events 表上的触发器拒绝一切 UPDATE 和 DELETE。更正、撤销、取代都靠追加新事件，历史始终完整。
  • 每条事件是带出处的说法，不是事实本身：它记下谁在什么时候报告了什么。
  • 清单在代码里。登记过的事件类型在 jarvis/state/event_log.py 的 _REGISTRY_ENTRIES；没登记的类型写不进去。这里不抄清单。
  • 类型的含义只加不改。要改一个事件的意思，就换一个新名字；老名字照旧能读。
  • payload 有界。截图、录音、终端输出这类大块内容存成文件，事件里只放引用和摘要。
  • 一个运行目录一条日志谱系，身份记在 event_log_metadata.log_epoch（ADR 0014）。

投影

投影只能从事件折出来，模型、工具和界面都不能直接改它。现在在用的投影：待确认的卡片、待填的卡片（ADR 0066）、还没结束的动作，和一块状态板（最近几轮、观察到的仓库和提交、电源变化）。每次决策读的是当时折好的快照。

记忆

memory.db 有三张表：

表存什么谁写
records逐字的对话，一行一句，标着是谁说的；留了录音时带录音路径每一轮
profile「关于你」：一行一个主题的长期事实，每一轮都放进系统提示首次设置写主人的名字；之后是模型调用 remember 和待填卡片的答案，同一主题覆盖旧的一行（ADR 0066）
summaries历史压缩出的摘要空闲时的压缩（第 5 章）
  • 记忆不能证明当前状态。「上周说过」不等于「现在还是」；当前状态要来自新鲜的工具结果或投影。
  • 现在还没有让主人查看、修改或删掉某一条「关于你」的地方；只能同主题覆盖，或者全部抹掉（第 9 章）。

数据格式与版本

  • 每个数据库把自己的格式写在 PRAGMA user_version。打开时低版本就地迁移上来；遇到比自己新的版本，不写任何东西就抛 NewerDataError，jarvis serve 以退出码 3 结束（ADR 0068）。所以旧版本 App 永远不会弄坏新版本写的数据。
  • 设置分三层，启动时读一次，后面的盖住前面的：随 App 发的出厂配置 config/jarvis.yaml；主人手写的 ~/.jarvis/settings.yaml，映射按键合并，列表和其他值整个替换；设置页写的 ~/.jarvis/settings.json，只认一张白名单里的键（ADR 0052）。

4. 动手的规矩

一轮怎么走

  1. 输入。一句语音、一段文字、一张卡片的答案或一个按钮。
  2. Tier 0。先对一张封闭的全句正则表（config/tier0_patterns.yaml）。命中就直接调那一行指定的工具，用语言表里的话回答，不调模型。每一行的工具必须是 regex_router 能用的，回答里不许出现「完成了」一类的词。在它之前还有一步：整句只是要助手再说一遍（「什么」「再说一遍」「没听清」，what? / pardon / say that again 这类），而之前有说出口的回答时，把最近那个回答的语音部分原样再说一遍，也不调模型。
  3. 模型的工具循环。没命中就把请求发给模型（组成见第 5 章）。一轮里带工具的请求最多 llm.max_tool_iterations 次（不写是 5，出厂配置是 40，ADR 0060）；到顶后再发一次不带工具的请求来收尾。
  4. 每个工具调用都先变成一个动作请求，过前置闸门，通过了才执行；闸门的每次判断和动作的每一步都记成事件。

风险等级与调用者

等级含义例子
L0读、观察看时间、读剪贴板、列备忘、读文件、等 worker 的结果、只读的插件工具
L1本地、可逆，或只往外读记备忘、remember、web_search、web_fetch、看一眼屏幕、打开网址或文件、插件里标明既不破坏也不碰外部世界的写操作
L2本地写、任务动作给 worker 补一句话
L3对外或不可逆派 Codex worker，发邮件和其他需要批准的插件工具
L4系统、管理配置、密钥、权限；不开放给模型
  • 策略的上限是 L3，确认线也是 L3：L3 的动作每次都要主人确认，L4 一律拒绝。
  • 插件（MCP）工具按服务器声明的提示定级（ADR 0033）：只读的是 L0；标明会破坏的，或没标明、可能碰外部世界的，要确认；只有标明既不破坏、也不碰外部世界的写操作不问。主人可以按插件改成总是问、只问写操作或从不问。
  • 能调用工具的只有两个调用者：jarvis_llm（模型）和 regex_router（Tier 0）。每个调用者只能用策略给它的那几个工具。

前置闸门

每个动作请求都过四项检查，四项都跑完再下结论，结果记成 gate.evaluated：

  1. 这个调用者能用这个工具；
  2. 需要目标的工具，目标来自可信的解析，不能是模型编出来的 ID；
  3. 风险不超过上限；
  4. 到了确认线的动作，带着有效的授权。授权在主人接受确认卡时生成，限定工具和目标，会过期，只能用一次，从不存起来复用（ADR 0012）。

确认卡（ADR 0062）

  • 要确认的动作变成一张卡片，卡片不过期；一次只等一张，新的请求替换旧的。
  • 按钮是正路。接受时可以当场改已有的字符串参数，改过的参数重新冻结成一张新卡再接受。
  • 问出之后，confirmation.ttl_ms（默认 10 分钟）内的第一句话也可以用是和否来回答。Jarvis 不分辨是谁说的（ADR 0090）。

不变量

I1 没有事件，就没有持久的状态变化。
I2 事件写下就不能改，只能追加更正。
I3 投影只读，只能由事件重建。
I4 没有生效的策略，就不动手。
I5 调用者只能用策略给它的工具。
I6 真实对象的 ID 不能编。
I7 高风险的动作必须确认。
I12 记忆不能证明当前状态。
I8 到 I11 随审核链退役（ADR 0019），编号保留。

交给 worker（ADR 0019）

后台的 worker 是 Codex app-server 的线程，模型用四个工具驱动它：派活、等结果、补一句话、关掉。派活是 L3，要确认；worker 只能在 tools.workers.roots 列出的目录里干活。worker 的最终消息原样交给模型和主人，Jarvis 不判定它做没做成。Agents 窗口里的会话是另一回事，见第 8 章。

5. 什么离开这台 Mac

Jarvis 没有自己的服务器。下面每一条外发，都去往主人配置的服务商、主人连上的服务，或者对话里要打开的网址。这一章是主人判断「什么离开了我的 Mac」的依据：新增一条外发，或者改了一条外发的内容，要在同一个提交里改这一章（ADR 0089）。

每一轮对话发什么（ADR 0044）

每一轮发给模型的请求固定由四部分组成，除此之外没有别的内容进去：

部分内容
系统提示规则文件 prompts/jarvis_v1.md 全文，后面接「关于你」的每一行（第 3 章）
历史对话记录逐字发送：从上一次压缩的摘要（有的话）开始，接着是摘要之后、且不早于 session.history_since 的每一句，只有原文，每天第一句前标上日期。session.recent_records 设成 N 时只发其中最近的 N 到 2N-1 句，前面加一行说明更早的有几句、用搜索工具去找；默认 0，全发
这一句主人这一轮说的话，前面加一块程序写的当前状态：时间、交互方式、已连接的应用、上一个回答的语音在哪里被打断（或者一个字都没念出来，只显示在屏幕上）、待确认的卡片、还在跑的动作；打开 realtime.response.slow_results 时，还有主人前面问的、另一轮还在答的问题。一轮的工具还没回来主人又说了话时，这一轮在工具结果后面加一句程序写的话：主人后来说了什么（另外答，这里不答），回答开头先点一下答的是哪个问题
工具模型这一轮能用的工具定义
  • 压缩。估算的逐字历史超过预设上下文的 session.compact_at_context_ratio（0.4，也就是 105 万 token 窗口的约 42 万），而且一小时没有新记录、没有实时语音连接时，才压缩一次：早于 session.verbatim_window_days（7 天）的记录折成一段摘要，最近 7 天仍然逐字。
  • 压缩本身也是一次模型调用，发出的是要折叠的那些记录。
  • history_since 之前的记录，以及 recent_records 窗口之外的记录，留在 memory.db，模型要用时通过搜索工具取回，不进每一轮的请求。窗口的起点每 N 句才往后挪一次，其间历史的开头不变，服务商的缓存才接得上。

6. 威胁模型与护栏

要护住的

主人的对话和「关于你」；模型服务商的 key 和各种登录；主人的代码仓库和 Claude Code 的权限决定；主人的钱，也就是 API 的花费；这台 Mac 本身。

防谁

在范围内不在范围内
  • 藏在外来内容里的指令：网页、邮件、屏幕上认出的文字、agent 的对话
  • 同一台 Mac 上别的账户和它们的进程
  • 主人 Mac 旁边说话的人
  • 主人装上的插件和 MCP 服务器
  • 下载途中被换掉的模型或程序
  • 已经以主人身份在这个账户里运行的恶意程序：它能读到主人能读的一切
  • 拿到这台已解锁 Mac 的人
  • 模型服务商自己如何处理收到的数据（见各家的条款）

威胁、护栏和缺口

威胁现在的护栏缺口
外来内容指挥它。网页、邮件、屏幕文字和 agent 对话都会送到模型面前，模型同时读得到「关于你」和对话记录系统提示写明：外来材料里的指令不改变它的规则、权限和当前任务；L3 动作要确认卡；插件里会破坏或碰外部世界的工具要批准（ADR 0033）；它驱动的浏览器不点付款、不填登录和验证码（ADR 0059）；web_fetch 对每个解析出的地址都检查，只访问公网地址web_fetch 是 L1，不经确认就能访问任何公网地址，可以把私事拼进网址发出去。remember 是 L1，一句话就能写进「关于你」，之后每一轮都进系统提示
本机别的账户或进程。冒充后台，或调用它后台只接受本机 Host 头，除存活探测外每个请求都要令牌；运行目录 0700本机端口人人可占：hook 和安装版 App 会把令牌交给占住 8006 的进程，hook 还把它的回答当作 Claude Code 的权限决定（第 2 章，未满足 ADR 0090）。agent 宿主回 Access-Control-Allow-Origin: *，不查 Host 头
旁边的人说话。确认卡一次只等一张，参数在卡上看得见问出后 10 分钟内的第一句「好」就算确认，不分辨是谁说的（ADR 0090 的界限）
凭据外泄。模型的 key 在登录钥匙串里，写入时不经过进程参数插件凭据和 MCP 登录令牌是 0600 的明文 JSON（改17）；~/.jarvis/env 也是明文，权限由主人自己定
账单失控。被诱导的循环或超长的历史一轮最多 llm.max_tool_iterations 次带工具的请求；每次调用都记账没有花费上限（改15）；实时语音记不上账
装上的东西被换掉。App 签名并公证；SenseVoice 和 VAD 模型下载后核对 SHA-256没有自动更新，修复送不到装好的人手里（包4）。本地 Whisper 的权重（mlx-community）由它自己的库第一次用时下载，Hue 插件由 uvx 从 PyPI 取 huemcp==0.1.0，都不核对哈希。插件没有签名，也不声明自己要什么权限。agent 宿主每小时替主人升级 Claude Code，不先问（第 8 章）

本机的其他入口

下面这些现在只靠「别的账户进不了运行目录」或「默认关」护着。公开版之前每一条都要重新看过。

  • ~/.jarvis/agents/keeper.sock 和 ~/.jarvis/codex.sock 不认证：连得上的进程可以让 keeper 以主人身份启动任意命令，或者驱动 Codex。
  • agent 宿主的钥匙和后台的令牌都能打开宿主的 /term，拿到主人的登录 shell，所以拿到其中任何一把就等于拿到这个账户（ADR 0095）。
  • 用量页打开后，用 Claude Code 和 Codex 存在这台 Mac 上的登录、以它们命令行的 User-Agent 去问用量；在页面上确认一次，会花掉一次 Codex 的限额重置（第 8 章）。

7. key、模型与花费

一把 key（ADR 0092）

默认打开的功能只用主人自己的一把 OpenAI key。别家的 key 只用来把某个功能换到那一家，或者打开一个默认关着的功能。首次设置只要这一把。Anthropic 作为那一把 key 是以后的决定：llm.provider: anthropic 的代码通路留着，不在首次设置里出现。

未满足ADR 0092：说出回答的声音还依赖 MiniMax，首次设置还问 MiniMax 和 Tavily 的 key。

key 放在哪

  • 模型服务商的 key 存在主人的登录钥匙串里：每个运行目录一项（服务名 Jarvis，账户是运行目录的路径），内容是 {环境变量名: key} 的 JSON。写入走 security -i 的标准输入，key 不出现在任何进程的参数里。用临时运行目录跑的测试后台读不到主人的 key。
  • ~/.jarvis/env 是主人自己写的明文 名字=值 文件，只补钥匙串和进程环境里都没有的变量。代码只读它、不写它，也不改它的权限；护住它的只有运行目录的 0700。
  • 安装版里 Agents 窗口的 Claude 会话用的 Anthropic key 单独存一项（账户是运行目录里 agents 文件夹的路径），同样经 security -i 写入。后台不读这一项；宿主只把它放进自己开的 Claude 会话的环境里（ADR 0094）。
  • 插件凭据和 MCP 的登录令牌现在是 0600 的明文 JSON（改17）。
  • 「抹掉全部数据」会删掉这两项钥匙串（第 9 章）。

花费

  • 每次调模型都记一条 cost.recorded，按 data/pricing.json 的价目表折成钱。
  • 现在只记账，不设上限（改15）。按秒计费的实时语音 gpt-live-1 在价目表里没有价格，记不上账。
  • 首次设置测 OpenAI key：先列一次模型（不花钱），再真的调一次对话模型，最多 200 个输出 token，发出去的提示里带着主人和助手的名字（改6）；最后只查模型列表里有没有后台要用的模型和 gpt-live-1。测 MiniMax key 会合成一个词的语音，测 Tavily key 会花掉一次搜索。
  • 后台每次启动都重测已存的 key：OpenAI 只列模型，不花 token；MiniMax 合成一个词，按字计费。
  • 安装版的 Agents 窗口存 Anthropic key 之前只列一次模型，不花钱。
  • 每一轮都带着逐字的历史，历史越长，每一轮越贵；压缩的门槛见第 5 章。

8. 和 Claude Code / Codex 的接口

Jarvis 最主要的价值建在两个别人的程序上。这一章列出它依赖对方的哪些文件、命令和接口；Claude Code 或 Codex 一改格式，从这里查起。

hooks

Claude Code（ADR 0049）Codex（ADR 0019）

放手后台不在、最近 10 秒没有伴侣在看、hook 进程没了、或会话在请求 3 秒后又往下写，都不给决定，交回 Claude Code 自己的对话框。Agents 窗口自己开的会话不经过它不需要

现在没有安装器：要主人自己拷脚本、自己改这两个设置文件，安装版也不带这两个脚本（改7）。卸载同样要手动。

读对方的状态

  • Claude Code 的会话（ADR 0046）：跑 claude agents --json 拿名单和实时状态，读会话的 state.json 和对话记录的末尾。不往 Claude Code 里装东西，不写它的文件。默认关（observer.claude_sessions.enabled）；hook 送来的标记不受这个开关影响。
  • 回后台会话一句话：打开上一条之后，主人可以在刘海里回一个空闲的后台 Claude 会话。后台在一个看不见的终端里跑 claude attach，把这一行打进去、回车、再断开；这个终端的环境里去掉了 ANTHROPIC_API_KEY，不走 API 计费。
  • Codex 的会话记录 ~/.codex/sessions：只有打开 daily_report.codex_sessions 时，日报才读它并发给模型。默认关。
  • Codex 会话的标题：刘海和 Agents 窗口读 ~/.codex/session_index.jsonl（设了 CODEX_HOME 就读那里的），最多十秒一次。
  • Ghostty：刘海上有 Claude 会话时，每 0.4 秒用 AppleScript 读一次 Ghostty 最前面那个标签页的标题，用来判断主人是不是正看着那个会话；点「打开」时也用 AppleScript 让 Ghostty 切过去或者新开一个标签页。
  • 主人的全名：首次设置用 id -F 读这个账户的全名，取第一个词作名字的默认值。

Agents 窗口（ADR 0073）

  • agent 宿主通过 Claude Agent SDK 驱动 Claude Code，用的是这台 Mac 上主人自己装的 claude 和它的登录；找不到时退回 SDK 自带的可执行文件。Codex 通过 codex app-server，也就是 Codex 自己的桌面 App 用的那套 JSON-RPC 接口。
  • 新会话默认开一个自己的 git worktree；删会话时只在 git 允许的情况下删掉它的 worktree，主人再按一次确认强删时，没提交的改动先存成仓库里 refs/startrail/trash/ 下的一个提交。对话从 agent 自己的记录里读回来；未读、搁置和归档的标记由后台保存（ADR 0069）。
  • 窗口能列出这台 Mac 上它还没有的 Claude Code 和 Codex 会话（SDK 的 listSessions、app-server 的 thread/list），主人选一个，就用同一个 id 在窗口里接着跑；两分钟内还动过的可能还在别处开着，要再按一次（ADR 0096）。
  • 窗口能看会话连着的 MCP 服务器，并替主人回答它们要填的表和要打开的网页。关掉一个 Claude Code 的 MCP 服务器，是 Claude Code 自己记在这个文件夹的配置里，终端里在这个文件夹开的 Claude Code 也一样关着；Codex 的服务器在这里只能重新读配置和登录，开关要改它自己的 config.toml。Codex 要主人验证身份的请求仍然拒绝。
  • 主人能在会话旁边另问一句，不打断它正在跑的那一轮，这一问一答也不进对话：Claude Code 用它自己 /btw 的那一问；Codex 学它自己的 /side，从这段对话开一个不存盘、只读、不问审批的分叉，答完就放掉。
  • Claude 会话清空上下文（/clear）后，Claude Code 换一个新的 session id 接着写。窗口里的一行按先后记下每个 id，在最后一个里继续，读回时依次读全部记录，并在清空处标一行（ADR 0088）。
  • 一键落地把会话的改动落到仓库的默认分支（origin 的 HEAD 指的那个，没有就 main，再没有就 master），两种走法：合入是提交、快进合进默认分支、重启、主人允许后推默认分支、删掉会话的 worktree；开 PR 是提交、主人允许后推会话的分支并用 gh 开 PR，不重启，worktree 留着。没装 gh 时停在推好的分支和远端给的开 PR 链接。门禁、重启命令和默认走法按仓库在设置里配；没配时 Jarvis 仓库用 docs/git-guide.md 的门禁和重启，别的仓库没有。Jarvis 仓库默认合入，别的仓库有 origin 时默认开 PR；会话就在默认分支上只能合入，不在自己 worktree 里的别的分支只能开 PR（ADR 0097）。
  • 宿主在启动时和之后每小时替主人跑一次 claude update，升级主人自己的 Claude Code。
  • 开发版里这些会话用这台 Mac 上 Claude Code 自己的登录。安装版里窗口开的每个 claude 只拿主人自己的 Anthropic key，或 Amazon Bedrock、Google Vertex 的设置，放在那个进程的环境里；都没有就不开 Claude 会话，并说缺什么。Claude Code 自己的登录不读、不改、不限制：宿主的环境、它开的终端和 claude update 都拿不到 key（ADR 0094）。
  • 在 App 里运行 Claude Code 要先同意 Anthropic 的商业条款。Allen 确认之前，安装版不带 Claude Code，也不开这个窗口（改19，定6）。

用量页（ADR 0018）

默认关（observer.usage.enabled），因为它要读别的程序的登录。打开后每 5 分钟问一次，数字变了才记一条 usage.state_observed；存下的只有百分比、金额、时间和套餐名，不存令牌。

哪一行用谁的凭据问哪里
Claude 订阅Claude Code 存在钥匙串里的登录（Claude Code-credentials），没有时读 ~/.claude/.credentials.jsonapi.anthropic.com/api/oauth/usage，User-Agent 用 Claude Code 命令行的 claude-cli/2.1.283
Codex 订阅~/.codex/auth.jsonchatgpt.com/backend-api/wham/usage，User-Agent 是 codex-cli。主人在页面上确认后，调 wham/rate-limit-reset-credits/consume 花掉一次限额重置（ADR 0048）
OpenAI API 花费OPENAI_ADMIN_KEYOpenAI 组织的 Costs、Usage、项目和 API key 列表接口
DeepSeek、MiniMax 余额各自的 keyapi.deepseek.com/user/balance；MiniMax 没有公开文档的 /account/query_balance

Claude、Codex 和 MiniMax 这三处都不是对外公开的接口，对方随时可能改掉或不再允许。公开版要不要带这一页，还没有定。

9. 安装、更新、卸载与数据

安装

  • 发的是一个 DMG 里的 App：Developer ID 签名、开了 hardened runtime、经过公证并装订。App 自带 Python、锁定版本的运行依赖和后台的代码（构建时编好字节码，运行时不往签名过的包里写任何东西）。
  • 只支持 Apple Silicon。最低系统版本还没设（包6）。
  • App 不在 Dock 里。第一次打开走首次设置：主人的名字、助手的名字、语言、OpenAI key、声音、系统权限和要连的服务。
  • 本地语音模型不在包里：后台发现缺了就在后台下载，核对 SHA-256，下好后自己重启一次；下好之前只能打字。

运行目录

一切状态都在运行目录里：默认 ~/.jarvis，可以用 JARVIS_RUNTIME_ROOT 换。后台每次启动都把它设成 0700。

位置装什么留多久
memory.db主人说的每一句和每一个回答、「关于你」、压缩摘要永久；代码里没有删它的路径，只有「抹掉全部数据」
mac_events.db事件日志：动作、确认、花费、观察到的状态，以及待办、知识、日报和工作状态的每一版永久，不裁剪
memory/audio/对话和听写的录音；每次听写还有一份 JSON，记着原话和润色后的文字（ADR 0084）默认不录；见保留期
artifacts/screen_artifacts/看一眼屏幕时的截图见保留期
aec-diagnostics/回声消除的诊断录音：麦克风、播放和消除后三轨默认不写（echo_diagnostics）；写了就不删
codex-hooks/Codex hook 事件的完整内容每种事件 10 MB，留两份旧的；不在保留期清理之内
agents/Agents 窗口的会话列表和设置、贴进会话的图片和文件、审阅时放回原样的文件留下的副本、宿主的钥匙 host-key（0600）、keeper.sock图片、文件和副本 30 天
settings.yaml、settings.json主人的设置（第 3 章）—
env主人自己写的明文变量（第 7 章）—
plugin-access.json、inherent-v2.token本机接口的令牌，0600；后者每次启动都换—
plugin-settings.json、plugin-credentials.json、mcp/插件设置、插件凭据和 MCP 登录令牌，0600 的明文（改17）—
logs/后台和伴侣的日志见保留期
models/本地语音模型下载一次，一直留着

表里只列装着主人的内容、凭据或令牌的位置。运行目录之外，Jarvis 还在钥匙串里存 key（第 7 章），App 自己在 ~/Library/Application Support 下有 Electron 的数据目录。

保留期（ADR 0067）

  • 录音默认不留（memory.retain_audio: false）。打开后，超过 memory.audio_retention_days（默认 30）天的删掉。
  • 截图超过 tools.screen.retention_days（默认 7）天的删掉。
  • 两者都按文件修改时间算，写 null 就永久保留；启动时和之后每小时检查一次。memory.db 里的对话记录不删，它指向的录音可能已经不在了。
  • 日志每个文件超过 10 MB 就挪开一份，连当前的最多留 3 份。日志只记发生了什么和长度，不记主人说的话、实时语音的转写或回答的文字。

导出与抹掉（ADR 0067）

  • 导出得到一个 zip：memory.db 和事件日志的一致副本、设置、录音和截图。不含 key、登录凭据、浏览器配置和语音模型。
  • 清掉录音立刻删除全部录音和截图，对话记录不动。
  • 抹掉全部数据在下次启动、打开任何文件之前执行：清空运行目录（只留 models/ 和 logs/），并删掉钥匙串里的 key。

现在这三件事只有后台接口，设置页里还没有入口（改16）。

更新

现在没有自动更新，也不检查新版本：装出去的每一份都停在那个版本（包4）。数据格式的规则保证旧版本不会弄坏新版本写的数据（第 3 章）。安装版和开发版现在共用 ~/.jarvis 和 8006（改18）。

卸载

现在没有卸载办法。删掉 App 之后，运行目录、钥匙串里的 key、App 自己的 Application Support，以及主人装进 Claude Code 和 Codex 设置里的 hooks 都还在。

10. 表面与注意力

表面

表面放什么
刘海里的她一眼能看的状态：agent 星星、待确认和待填的卡片、Claude Code 的权限请求、正在听和正在说
面板和对话页工作状态、对话记录、证据和操作；面板可以拆成单独的窗口（ADR 0080）
Agents 窗口主人在 Jarvis 里开的 Claude Code 和 Codex 会话（第 8 章）
语音即时的结论、必要的问题和简短的提醒。唤醒词或免唤醒模式开始；说出口的就是回答本身（ADR 0040）。唤醒词和点一下一样打开免唤醒模式；主人说「退下」「没事了」「就这样吧」这类话，或者助手说完、主人上一句成了一轮之后 10 秒没有新的一轮，就退出；附和、单字和听不出字的声音不算一轮，也不让它多开；说「等我一下」它多等 1 分钟。这些话都不算一轮（ADR 0102）。免唤醒模式里主人在助手说话时开口，助手先放低声音，话一长就停在原处，由识别出的字决定（ADR 0100）：没有字、只是附和或一个不成回答的字，助手从原处接着说，不算一轮；要它停的话让它停下，也不算一轮；别的话让它停下，算新的一轮。停下时还在写的回答一并取消。能回答确认卡的单字（对、好、是、yes）总算一轮。放低声音不解除静音

Agents 窗口不在最前面时，它的会话做完、等主人回答或出错，Mac 发一条系统通知，点开就到那个会话。三种可以分别关掉；窗口开着时通知不出声，同一个会话 20 秒内只发一条。窗口开着时 App 出现在 Dock 里，不带角标。别的事还不发系统通知：首次设置请求通知权限时说的「早报到了，在右上角告诉你」还没有做。

规则

  1. 安静优先。默认不打扰；主动开口要有证据和理由。
  2. 表面不拥有真相。界面只读投影、发事件，或发出经过闸门的请求；它缓存布局，不缓存任务状态。
  3. 语音不承载密集的证据。长的、要核对的内容放面板。
  4. 面板是默认的工作表面。工作状态先给面板，不先给语音。
  5. 通知要限流。只用于要紧的事或值得主人看一眼的结果。
  6. 环境动作可逆、低噪。开关灯这类动作能撤回，不制造声响。
  7. 每次开口都有来处。表面上的每一次输出都能追到一个事件或一次决策。

注意力

现在只有一个固定的工作模式，注意力是几条固定规则：没有打分，也不从主人的反馈里学。专注模式做出来时，写成第一个真正的模式，并先写 ADR。
