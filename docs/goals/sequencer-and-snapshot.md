# Goal: sequencer-and-snapshot

## Goal
The daemon has one level-triggered `InherentViewSequencer` that turns committed Event Log rows into ordered, cursor-carrying v2 `view.delta` envelopes, and serves every new v2 client a bounded, hashed, paged snapshot that must be ACKed before a server-driven catch-up hands it to the live stream — all behind a default-off flag whose off state leaves v1 byte-identical.

## Why
Card 1 opens the authenticated v2 socket and then deliberately sends nothing ("After a successful hello this card sends nothing further and keeps the socket open", docs/goals/v2-envelope-and-identity.md). Today's only producer is a 10 ms poller that fans out row-by-row with no cross-source ordering, no cursor on the wire, and no history for a reconnecting client, so a client that connects mid-turn or reconnects sees a truncated conversation.

## Current behavior
- No Inherent view projection exists. jarvis/state/projections.py builds only `ClaimEvidenceProjection` (:155), `TaskLedger` (:397), `RecentTrace` (:583), `StatusBoard` (:860), `EntityRegistry` (:1064) and `PendingConfirmations` (:1327); `ProjectionSet` (:1441) and `rebuild_projections` (:1465) name no response-group or action view.
- Delivery is poll-driven. `_response_watcher` (jarvis/runtime/inherent_loop.py:987-1053) and `_user_intent_watcher` (:557-637) both `await asyncio.sleep(poll_interval_s)` (:1051, :635) with `_DEFAULT_POLL_INTERVAL_S: float = 0.01` (:150).
- The response watcher holds one cursor over three types, `WHERE id > ? AND type IN ('surface.response_open','surface.response_chunk','surface.response_emitted') ORDER BY id ASC` (`_SELECT_RESPONSE_EVENTS_AFTER_ID_SQL` :204-223, read by `_fetch_response_events_after` :356-368). Ordering is guaranteed only inside that one query — ADR-0003 D16, restated at :994-1000.
- `CommittedEventBus` (jarvis/state/committed_event_bus.py:16-57) is constructed only when `realtime.enabled` is true (jarvis/runtime/__init__.py:1473-1477) and in `serve_inherent` reaches only the boot response reconciler (jarvis/runtime/inherent_loop.py:90, :443, :464, :2929).
- **No `surface.response_*` row is ever published on that bus.** jarvis/surface/cli_render.py:175, :214 and :499 call `emit_event` with no `committed_event_bus` argument, and `emit_event` publishes only when that argument is supplied (jarvis/state/event_log.py:1558, :1594-1595). Production wake for panel rows is therefore timer-driven today, and stays timer-driven after this card.
- `InherentBroadcaster` translates each row 1:1 into a wire envelope (`broadcast_open` jarvis/surface/inherent_output.py:134-160, `broadcast_chunk` :162-184, `broadcast_done` :186-205) and sends it immediately to every socket (`_send_all` / `_send_all_locked` :356-411).
- `register()` sends only the retained `voice_capability` envelope and no history (jarvis/surface/inherent_output.py:110-127; cache at :97 and :286-320).
- With no client connected the envelope is dropped with a WARN (jarvis/surface/inherent_output.py:384-392).
- No sequence number, ACK, catch-up, snapshot, or per-client cursor exists in jarvis/surface/inherent_server.py or jarvis/surface/inherent_output.py. `ws_endpoint` accepts, registers, drains `receive_text` in a loop, unregisters (inherent_server.py:359-389).
- The Swift client dispatches deltas only — five ops, no cursor, no snapshot (desktop/inherent-swift/InherentCard/BridgeBackend.swift:32-45; `BridgeTurnGate` :64-94).
- `realtime` in config/jarvis.yaml:144-243 has sub-blocks `enabled`, `concurrency_safety`, `response`, `actions`, `input`, `streaming_output`, `single_audio_ingress` — no `inherent` block. The block comments state the convention: a sub-flag "additionally requires realtime.enabled", and "an invalid combination downgrades once, with one warning, to the complete legacy batch path" (:151-157); `realtime.input` records that "ADR-0008 §6 names no key for this block; the shape mirrors realtime.actions" (:188-189).
- Layer contract: `cli` > `runtime` > `decision | execution | surface | deployment` > `state` > `constitution | shared` (.importlinter:19-30). inherent_server.py:24-32 additionally restricts itself to stdlib, fastapi/pydantic/starlette and two L5 siblings, taking everything else as injected callables.
- Card 1 (merging first) adds `new_log_epoch` / `new_boot_id` / `new_connection_id` / `new_client_instance_id` to jarvis/shared/realtime.py — which today mints only response/group/authorization IDs (:214-308) — plus an event-log metadata table holding `log_epoch` at `user_version` 2 (jarvis/state/event_log.py:1326).

## Target behavior
- Ownership follows ADR-0014 D9:630-632 and §12:1739-1743:
  - **L2 `jarvis/state/inherent_view.py` (new)** owns the fold. It derives the response-group view truth from `surface.response_{open,chunk,emitted}` rows and returns immutable snapshots. It imports only L1 (`jarvis.constitution`) and L2 (`jarvis.state`) — "L2 owns all fold logic and immutable projection snapshots" (D9:630).
  - **runtime `jarvis/runtime/inherent_view_sequencer.py` (new)** owns "sequencer lifecycle, scan watermark, wake/drain, and client orchestration" (D9:631) and is "the only producer of durable v2 panel deltas" (D9:634).
  - **L5 `jarvis/surface/inherent_presenter.py` (new)** maps already-derived truth to safe wire DTOs and "never derives canonical action state, confirmation validity, or cancellability" (D9:632). It imports only L1, L2 and `jarvis.shared`.
  - **runtime `jarvis/runtime/inherent_hub.py` (new, minimal)** holds per-connection state: snapshot staging, the awaiting-ACK record, the adoption deadline and the live frontier. Bounded queues, byte windows and backpressure are the flow-control card's extension of this module, not this card's.
- The wake is level-triggered and cannot be lost, exactly per D9:614-626: a notification sets one `asyncio.Event`; the drain clears the flag, captures `H = MAX(events.id)`, reads every row `scan_cursor < id <= H` ascending, maps each relevant transition to one `view.delta`, advances `scan_cursor` across irrelevant rows too, sets `scan_cursor = H` only after all rows projected, and repeats immediately if the flag is set again or a fresh MAX exceeds the cursor. "A periodic timer sets the same flag as recovery; it is never another payload producer" (D9:626) — that timer keeps the existing 10 ms cadence and is the wake that actually fires in production, because nothing publishes `surface.response_*` on the bus (see Current behavior).
- `serve_inherent` subscribes the sequencer to `runtime.committed_event_bus` when the bus exists; the subscriber only sets the flag and never carries a payload (D9:611 "neither the direct bus payload nor the watcher directly fan out an independent client message").
- Every durable envelope carries `event_cursor = events.id` and no `ephemeral_sequence` (D6:419-420). That cursor is the card's ordering number: within one `log_epoch` "physical IDs never regress, repeat, or renumber" (D6:456), and "Cursor gaps are legal because not every Event Log row is visible to Inherent. Cursor regression is not legal" (D6:434). `message_id` is the source `event_uid` (D6:426-427); a row that changes several entities emits one envelope whose `payload.changes` is an ordered array (D6:428-431).
- Startup drains through the current high-water before any v2 client is accepted (D9:636).
- **Every new socket gets a snapshot** — "V2.0 always chooses `resume_mode=snapshot` on a new socket" (D7:521-523). There is no client-supplied resume cursor and no retained envelope buffer; the server "stores no duplicate delta payload buffer" (D8:576).
- Snapshot and handoff run exactly as D8:557-583: (1) a mailbox command drains through captured high-water `H`, registers the client `snapshotting`, and clones one bounded immutable checkpoint at `H`; (2) a per-client task outside the sequencer gives that checkpoint to the presenter, which builds and encodes `SnapshotPlan(H, checkpoint, pages)` and "never re-folds the full Event Log on the live path" (D8:569); (3) it records the plan/H/hash as awaiting ACK, then transmits `snapshot.begin` / `snapshot.page`* / `snapshot.end` and waits for the ACK outside the sequencer while the sequencer keeps draining global truth, serving other clients, and skipping live fan-out to this one; (4) no durable `event_cursor > H` reaches that client before ACK; (5) the verified ACK posts a command that captures `B = MAX(events.id)`, clones the client's checkpoint at `H`, and folds every row `H < id <= B` in ascending order — re-read from the durable log, since nothing was buffered; (6) still inside that one command, enqueue the catch-up and atomically set `live_frontier = B`, then discard the checkpoint — "If replay exceeds its frame/byte budget, close/resnapshot that client; never expose a partial catch-up" (D8:582-583); (7) events committed after `B` append behind the catch-up through the same actor, and no notification path may overtake it (D8:584-585).
- Each snapshot page is at most 64 KiB (D8:555). `snapshot.end` carries `content_hash` = SHA-256 "over the exact UTF-8 bytes of every complete `snapshot.page` server frame, ordered first by the section order advertised in `snapshot.begin` and then by `page_index`, excluding begin/end and WebSocket framing. The server hashes the byte slices it sends" (D8:586-591), plus the same `snapshot_id`, page counts, view schema and `through_cursor` as `begin`.
- The inline document budget is 16384 bytes of UTF-8 per response document body. A body at or under it is inlined; a larger body ships a truncated preview plus the durable reference (source `response_id` and `event_uid`) — "Large document bodies above the inline budget are represented by a projection-backed artifact reference plus a bounded preview" (D16:1082). The fetch path for that reference is a later card.
- ACK validity per D11 rule 7 (:816-819): same connection and log epoch, `last_acked_cursor <= through_cursor <= last_sent_cursor`; a regressing ACK is ignored only as an exact duplicate; an ACK past last sent is a protocol error; a snapshot ACK must match the active snapshot ID and `H`. The ACK frame shape is D11 rule 6 (:797-812). A snapshot with no ACK progress for five seconds closes that client with resync-required (D11 rule 9, :822-824).
- Snapshot scope is bounded per D16:1072-1080: every non-terminal response group, every group linked to an open action or pending confirmation, the most recent 20 terminal groups, the open/recent actions those groups need, the one pending confirmation, and freshness/capability metadata. Older content stays in the Event Log and is not copied into every reconnect snapshot.
- This card fills only the `response_groups` section, from the L2 fold over the three `surface.response_*` types the v1 watcher already reads (inherent_loop.py:204-223). `snapshot.begin.section_order` and `counts` name that one section; `actions`, `pending_confirmation`, `capabilities` and `surface_notices` are absent until the card that lands the D13/D14 projections.
- Flag `realtime.inherent.v2_sequencer.enabled`, default false, additionally requiring `realtime.enabled: true`; an invalid combination downgrades once with one warning, matching the wording already used at config/jarvis.yaml:151-157 and :162-170. Off means the sequencer and hub are never constructed and the v1 wire is byte-identical.
- The v1 watchers, the v1 route and `InherentBroadcaster`'s v1 envelopes are untouched; both paths may run at once while the flag is on.

## Boundaries and non-goals
- Layers that may change: L2 (one new module), L5, runtime, config, tests, scripts.
- Must not change: any v1 frame, the `/inherent/ws` route, `InherentBroadcaster` behavior, the 10 ms watchers, `jarvis/state/projections.py`, `jarvis/surface/cli_render.py`, or any Swift file.
- Non-goals: per-client flow control and the rest of D11 (bounded queues, byte windows, ephemeral coalescing map, ACK batching at 25 messages / 100 ms, control-lane fairness) — the `per-client-flow-control` card; threading `CommittedEventBus` into the response emit path (lane A owns that runtime hotspot); input endpoints; control messages (`control.stop_speaking`, `input.ptt_*`, and `state.resync_request` beyond forcing a fresh snapshot); ephemeral messages and `ephemeral.baseline`; the artifact fetch endpoint behind an over-budget document reference; the Swift consumer (card 2 and later); removing or rewiring the v1 watchers.

## Rejected approaches
- Client-supplied last-seen cursor resume with a retained envelope window — D7:521-523 fixes `resume_mode=snapshot` for every new v2.0 socket and permits incremental resume "only after a client proves it retained a complete state with the same log epoch and view schema"; D8:576 says the server "stores no duplicate delta payload buffer".
- Putting the sequencer or the fold in L5 — D9:630-632 assigns fold logic to L2 and lifecycle/watermark/wake/orchestration to runtime; §12:1743 names `jarvis/runtime/inherent_view_sequencer.py`.
- Publishing `surface.response_*` on `CommittedEventBus` by threading the bus into jarvis/surface/cli_render.py:175/:214/:499 — it would give the sequencer a real low-latency wake, but it changes the render path in lane A's hotspot and is not needed for correctness: the recovery timer already guarantees the drain.
- Reusing `InherentBroadcaster._send_all` for v2 — it fans out one shared dict to every socket with no per-client cursor (inherent_output.py:356-411), which cannot express a per-client snapshot barrier, and §12:1753 forbids it.
- Deriving the snapshot by re-folding the full Event Log per connection — D8:569-570 forbids re-folding on the live path; a raw full-log rebuild is a startup/maintenance fallback only.
- Minting a new sequence counter alongside `event_cursor` — D6:419-420 fixes `event_cursor = events.id` for durable deltas and gives ephemeral frames their own `ephemeral_sequence`; a third number would be a second ordering truth.
- Adding the fold to `jarvis/state/projections.py` — that module's `ProjectionSet` (:1441) is rebuilt over the whole log for the L3 projections; the Inherent view needs an incremental fold with its own bounds, and mixing them would re-fold everything on every wake.
