# Goal: incremental-tts-from-permitted-segments

## Goal
`voice_media` starts speaking a routine streaming response from its first durable permitted segment instead of waiting for `surface.response_emitted`, and a mid-stream `response.cancelled` / `response.failed` reaches the active playback and stops it.

## Why
A2 (`wire-routine-streaming`) makes `surface.response_chunk` rows land while the LLM is still generating, but every TTS start is still gated on `surface.response_emitted` (jarvis/surface/voice_media.py:1893-1896), so the whole latency win is thrown away at the last hop. Nothing else in the program speaks earlier.

## Current behavior
- Base: lane A2 is merged on `realtime-integration`; this card sits on top of it. Facts below are at `73fb285` (pre-A2) and hold unchanged by A2's boundary list, which forbids touching `voice_media.py`, `voice_tts.py`, `_tts_watcher`, `inherent_output.py`.
- Citations are at `realtime-integration` `73fb285`, before A2 merged; the files that moved are `runtime/__init__.py` and `config/jarvis.yaml` (`voice_media.py` and `inherent_loop.py` did not move) — the implementer re-confirms `runtime/__init__.py` and `config/jarvis.yaml` line numbers and the streaming `surface.response_open` payload after `git merge realtime-integration`.
- The media owner accepts exactly three event types: `_RESPONSE_EVENT_TYPES = {surface.response_open, surface.response_chunk, surface.response_emitted}` (jarvis/surface/voice_media.py:68-70), used as the ordered-drain filter (:1797). `_tts_watcher` fetches its own separate literal tuple of event types (jarvis/runtime/inherent_loop.py:1122-1126 via `_fetch_events_after` :329-353), not `_RESPONSE_EVENT_TYPES`.
- `_handle_event` only buffers a chunk into `response.chunks` (voice_media.py:1864-1892) and returns; `_schedule_response` is called only from the `surface.response_emitted` branch (:1893-1897).
- The silent-channel guard reads `attention_channel` from the `surface.response_open` header and terminalizes the response before any chunk is buffered (voice_media.py:1837-1839); `_tts_watcher` drops the same turns one layer earlier (`_drop_for_silent_channel`, inherent_loop.py:371-413, called at :1132-1140). `_drop_for_silent_channel` forgets a suppressed turn id only on `surface.response_emitted` (:411-412).
- `_ResponseBuffer.speech_segments()` (voice_media.py:304-326) joins every buffered chunk, lexes `<voice>`/`<document>` over the joined text once (:307-309), and maps spans back to chunk identities; `speech_text()` (:328-330) concatenates them. tests/integration/test_wave2_streaming_media.py:1618 and :1660 pin tag splits across chunk boundaries. After A2 a routine chunk's text is tag-free voice body, but the legacy `render_response` path can still put whole `<voice>…</voice><document>…</document>` text in one chunk.
- The two producers are already distinguishable in the durable `surface.response_open` payload: the streaming emitter writes `kind="stream"` (jarvis/state/stream_emission.py:318-328), the legacy renderer writes `kind="text"` (jarvis/surface/cli_render.py:181). `kind` is a required payload field (jarvis/state/event_log.py:920-924).
- `_play_response` snapshots the whole segment list and the whole speech hash once, before any audio (voice_media.py:2004-2005), emits `surface.playback_started` carrying that full-text `speech_text_hash` with `source_event_id` = the buffer's `source_event_id` (:2021-2035, set to the emitted uid at :1895), then walks the fixed list in `_stream_with_prefix_fallback` (:2100-2277), emitting one `surface.playback_segment_prepared` per segment bound to `(sequence, speech_text, speech_text_hash, segment_hash, source_chunk_event_uid)` (:2113-2129). `_drain_and_complete` writes `surface.playback_completed` with the same full-text hash (:2478-2541, hash passed at :2048/:2532).
- That hash is a durable contract, not a diagnostic: `PlaybackHistory._start` binds `speech_text_hash` from `surface.playback_started` (jarvis/state/conversation_playback.py:104-132), `_cursor` rejects any checkpoint/terminal whose `speech_text_hash` differs (:173), and on `surface.playback_completed` requires `text_hash("".join(prepared segments)) == self.speech_hash` (:192-197). Failure marks the whole response projection inconsistent. `surface.playback_started`'s `source_event_id` must be in `surface_sources`, which holds both the `surface.response_open` and `surface.response_emitted` uids (jarvis/state/conversation.py:161-162). `surface.playback_started` has `optional_payload=()` today (jarvis/state/event_log.py:786-796).
- No cancel event reaches the media owner. `response.cancelled` / `response.failed` are registered L3 event types carrying `response_id`, `response_group_id`, `turn_id`, `reason` plus optional `committed_prefix_hash` (jarvis/state/event_log.py:761-782), but `_tts_watcher` never fetches them (inherent_loop.py:1122-1126) and `_RESPONSE_EVENT_TYPES` excludes them, so once speech starts on chunk 1 nothing stops it. `_interrupt_active` (voice_media.py:2577-2608) already implements the exact stop: tombstone, cancel provider I/O, durable `surface.playback_interrupted`, release — it is private and has no external caller.
- `ActivePlaybackRegistry.classify` (voice_media.py:379-481) is not type-closed: an unknown type with a registered `response_id` falls through to `accepted` (:481). Chunks after `surface.response_emitted` are rejected as `terminal` (:435-442). `terminalize()` (:487-497) blocks every later delivery for that response.
- `submit_event` marshals from the watcher thread onto the media loop with `asyncio.run_coroutine_threadsafe` (voice_media.py:697-714).
- `StreamingMediaConfig` (voice_media.py:223-241) and `streaming_media_config_from_mapping` (:2967-3010) parse `realtime.streaming_output.*`; the block lives at config/jarvis.yaml:204-221 with `enabled: false`. `enable_macos_say_fallback` (:2992-2997) is the existing boolean-key pattern.
- The 60-code-point safe-subclause cap is enforced only in the L3 gate (jarvis/decision/stream_gate.py:86), so a permitted speech segment is already short enough to speak alone.
- The conservative heard-text rule is in jarvis/surface/voice_ledger.py:275-296 (`snapshot()` counts a segment only when closed, below the estimated audible cursor, and `audibility_class == "normal"`); the generation CAS is in jarvis/surface/voice_tts.py:1071 (`activate_generation`).

## Target behavior
- Flag: `realtime.streaming_output.speak_from_segments`, boolean, default `false`, parsed alongside `enable_macos_say_fallback`. Off means the response never starts playback before `surface.response_emitted`; the terminal wiring is ungated and also drops a cancelled run's buffer when the flag is off.
- With the flag on, incremental speaking is enabled for a response only when its `surface.response_open` payload has `kind == "stream"` — i.e. the row came from `append_permitted_segment`, so every later chunk is one gate-permitted segment. A `kind == "text"` response (legacy full-text `render_response`) keeps today's behavior exactly: buffer, then speak at `surface.response_emitted`.
- Conservative tag guard: a `<voice>` or `<document>` tag that appears on a `kind == "stream"` response before playback started falls back to the emitted-time path (no incremental playback for that run); a tag that appears after playback started stops preparing further segments, calls `_fail_active(reason=stream_chunk_tagged)`, and terminalizes the response. A2 guarantees tag-free stream chunks; this keeps the joined-text lexer (`speech_segments()`, which re-lexes the joined text at :306-309) the single owner of tag handling and leaves tests/integration/test_wave2_streaming_media.py:1618/:1660 semantics untouched.
- On the first chunk of an eligible response, the media owner starts playback the same way `surface.response_emitted` starts it today (lease minted through `activate_generation`, `surface.playback_started` emitted, one `_play_response` task). `surface.playback_started` is emitted exactly once per generation, at the first segment; its `source_event_id` is the `surface.response_open` uid, which `surface_sources` already accepts.
- The playback segment loop consumes segments as they arrive instead of a snapshot list: each newly durable chunk becomes one `surface.playback_segment_prepared` + one provider segment, in `sequence` order, with the same per-segment binding fields as today. The loop ends only after the buffer has seen `surface.response_emitted` and every buffered segment has been prepared; the remainder unspoken at that point is flushed then.
- At `surface.response_emitted`, in addition to that remainder flush, the media owner speaks `voice_text` minus the already-spoken prefix (the chunk concatenation already committed to playback) as one final segment. Today this suffix is never spoken: `decision/__init__.py:2946-2997` seals the run on any gate rejection, `cli_render.py:472-517` sends no chunk for that suffix, and the emitted branch (`voice_media.py:1893-1896`) reads only `speech_text()` (the chunk concatenation).
- `surface.response_emitted` on an already-speaking response does not schedule a second playback and does not enqueue the response behind itself in `_after_drain`; it marks the buffer complete so the segment loop can finish.
- Speech-hash contract under incremental start (this is a documented-invariant change, see Docs to sync): the full speech text is unknown when `surface.playback_started` is written, so an incremental lease declares that explicitly with a new optional `incremental: true` on `surface.playback_started`, and carries the hash of the first prepared segment as `speech_text_hash`. `PlaybackHistory._start` treats an incremental activation as no full-text commitment (`speech_hash` unbound); `_cursor` keeps its monotonic-prefix and per-segment-concatenation rules unchanged and, on `surface.playback_completed`, binds the terminal's `speech_text_hash` to the concatenation of prepared segments instead of comparing it against the activation hash. Non-incremental activations keep today's exact equality. `surface.playback_completed`'s hash is therefore computed after the last segment, not at play start.
- What still proves every checkpoint is the per-segment binding, unchanged: each `surface.playback_segment_prepared` carries its own `speech_text` and `speech_text_hash` bound to `source_chunk_event_uid` and `segment_hash` (voice_media.py:2113-2129, validated at conversation_playback.py:137-158), and `_cursor` still accepts a cursor only when its `heard_text` is exactly the concatenation of prepared segments through that sequence (:184-191). Losing the full-text commitment at activation removes a redundant check, not the evidence.
- `_cursor` (jarvis/state/conversation_playback.py:173) and the completed rule must tolerate incremental checkpoints that carry no `speech_text_hash`.
- The conservative heard-text rule is unchanged: heard state still never exceeds what the ledger proved (`voice_ledger.py:275-296` — a segment counts only when closed, below the estimated audible cursor, and `audibility_class == "normal"`), and an interrupted incremental response therefore contributes only its fully-played prefix. Incremental speaking makes partially-spoken responses ordinary rather than exceptional; it does not loosen what counts as heard.
- An incremental response must never drive `PlaybackHistory.consistent` to false. The projection over a complete incremental trail (`surface.response_open(kind="stream")` → chunks → `playback_started(incremental=true)` → per-segment `playback_segment_prepared` → checkpoints → `playback_completed`) stays consistent, and its `spoken_heard` equals the proven prefix.
- Mid-stream cancel: `_tts_watcher` also fetches `response.cancelled` and `response.failed`, and `_RESPONSE_EVENT_TYPES` admits them so the ordered drain does not skip them. When such an event names the response whose playback is active, the media owner calls `_interrupt_active` (durable `surface.playback_interrupted`) and terminalizes that response id, so no further `surface.playback_segment_prepared` is written and no further chunk is accepted. When it names a response that is buffered but not active, the buffer is dropped and the response terminalized. The durable response terminal stays L3-written; L5 writes only its own playback terminal.
- After `_interrupt_active`, the cancel path drains and terminalizes the queue like the sleep path (`inherent_loop.py:1381-1385`), so `_after_drain` is never left pending.
- `_drop_for_silent_channel` also discards a suppressed turn id on `response.cancelled` / `response.failed`, so a cancelled silent turn cannot leak an entry in `silent_turns`.
- The silent-channel guard stays strictly ahead of speaking: it is evaluated on `surface.response_open`, which precedes every chunk in Event Log order, so a `queue_review` / `silent_log` response is terminalized before a first chunk can start playback.
- `response_timeout_s` (`asyncio.timeout`, 45 s default) must not fail a run only because playback of already-permitted segments is still in progress; its scope ends at `surface.response_emitted` / the run's terminal event. The implementation picks the mechanism (bound or renew per segment) and records the choice under Progress.
- Unchanged: the conservative heard-text rule (voice_ledger.py:275-296) and generation CAS (voice_tts.py:1071), the 60-char gate cap (stream_gate.py:86), `finalize_stream`, `speech_segments()`'s lexing rule, the `after_drain` lane and foreground-supersede arbitration, macOS `say` fallback, and every behavior with the flag off.

## Boundaries and non-goals
- Layers that may change: L5 `voice_media.py`, L2 (`event_log.py` one optional field, `conversation_playback.py`), runtime `inherent_loop.py`, config, tests.
- Must not change: jarvis/surface/voice_ledger.py (heard-text rule, generation CAS), jarvis/decision/stream_gate.py (the 60-char cap), jarvis/decision/stream_finalize.py, any other file under jarvis/decision (read-only), jarvis/surface/voice_tts.py, jarvis/surface/inherent_output.py, desktop Swift sources, the terminal-only-through-CAS ownership, `speech_segments()`'s tag lexing, and all behavior with the flag off.
- The legacy (non-streaming) pipeline path ignores the new response-terminal event types (`response.cancelled` / `response.failed`) silently; accepted and stated, not fixed in this card.
- Non-goals: barge-in / ADR-0014 Stop controls; sibling speech/document ResponseRuns (D7); a delivery terminal for cancelled runs; provider-side continuation from a committed prefix; changing when L3 writes the response terminal; a correction run after a failed streamed run re-speaking from the start (de-duplicating the already-spoken prefix is out of scope).

## Rejected approaches
- Holding `surface.playback_started` until `surface.response_emitted` so the full-text hash stays exact — it defeats the goal of early playback (no segment would be spoken before the response is fully emitted, contradicting this card's own live-run evidence that `playback_started` precedes `response_emitted`) and breaks the crash-recovery card's boot-cursor assertions; the chosen approach accepts an unbound lease while audio is already playing instead.
- Re-lexing tags per chunk so incremental speaking also covers the legacy path — `speech_segments()` deliberately lexes the joined text once, and a `<` opening mid-stream would retroactively change earlier segments after they were spoken.
- Routing cancel through a new L5-owned response terminal — the response terminal is L3's, written through the terminalizer CAS; L5 may only write its own playback terminal.
- A new `surface.*` event to announce "this response streams" — `surface.response_open.kind` already carries it durably.
