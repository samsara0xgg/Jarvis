# Goal: per-client-flow-control

## Goal
Every v2 Inherent client owns bounded, prioritized lanes — a 32-frame control-ack lane, a 256-frame / 1 MiB durable-snapshot lane and a 32-key ephemeral coalescing map — so that a slow or silent client is closed with `server.resync_required` and a retryable code instead of growing an unbounded queue or stalling anyone else, while the Swift client returns a cumulative `transport.ack` batched at 25 durable messages or 100 ms so a healthy client is never closed by the ack-stall rule.

## Why
The sequencer-and-snapshot card deliberately shipped only the minimal half of D11 and named the rest here (jarvis/runtime/inherent_hub.py:3-8, docs/goals/sequencer-and-snapshot.md "Non-goals"). Three of its accepted Progress advisories are this card's opening items: no exception guard in `_run_snapshot` or the sequencer `_run`, a catch-up with a frame budget but no byte budget, and no per-client bound at all. Today one client that stops reading its socket grows one Python-heap queue without limit and is never closed, and no client ever ACKs a durable delta, so D11 rule 9 would close every healthy client the moment it is enforced. Rules 8 and 9 therefore have to land together.

## Current behavior
- `InherentClient` holds **one unbounded** `asyncio.Queue[str | None]` for every class of frame (jarvis/runtime/inherent_hub.py:96). `_enqueue` calls `put_nowait` unconditionally and tracks nothing but `last_sent_cursor` (:188-190).
- One FIFO sender drains that queue and awaits `send_text`; only an exception ends the connection, never a depth (:245-255). There is no priority: snapshot frames are pushed straight onto it (:216-217) and durable deltas arrive through the lane's `enqueue` (jarvis/runtime/inherent_view_sequencer.py:183-186).
- The only window state is `last_sent_cursor` / `last_acked_cursor` (inherent_hub.py:99-100, exposed :107-115). No unacked frame count and no unacked byte count exist, so D11 rule 5 is half-implemented.
- ACK exists only for the snapshot. `_apply_ack` sets `_ack_event` while a snapshot is awaiting (:158-163) and otherwise advances `_last_acked_cursor` (:166-171) — a path nothing currently exercises, because the Swift reducer emits `.sendAck` **only** on snapshot adoption (desktop/inherent-swift/InherentRealtime/RealtimeReducer.swift:215) and `applyDurable` returns mutation effects only, never an ACK (:220-258).
- Two close paths exist, both through `_fail` (inherent_hub.py:257-271): `1002` for `reason == "protocol_error"`, `1008` for everything else (:61-62, :268). The reason string is simultaneously the WebSocket close reason (:270) and the `inherent_v2_client_closed` trace attribute (:263-267).
- **No `server.resync_required` frame is produced anywhere.** `grep -rn resync_required jarvis/ tests/ scripts/ desktop/inherent-swift/` finds only the close-reason literal at inherent_hub.py:228, :235 and the assertion at tests/integration/test_inherent_sequencer.py:705. D11 rule 3's control-lane notice does not exist.
- The catch-up budget is frames only: `CATCH_UP_FRAME_BUDGET = 256` (jarvis/runtime/inherent_view_sequencer.py:55), raised as `CatchUpBudgetExceededError` at :236-241 and turned into a 1008 close at inherent_hub.py:233-236. No byte budget, although D8 step 6 says "frame/byte budget" (docs/adr/0014-inherent-realtime-ux.md:582-583).
- The sequencer's `_run` logs and **re-raises** any exception (jarvis/runtime/inherent_view_sequencer.py:291-293), which kills the one producer for every client; `_run_snapshot` wraps nothing around `begin_snapshot` / `build_snapshot_plan` (inherent_hub.py:207-224).
- No ephemeral frame is produced anywhere. `ServerEnvelope` already refuses an `ephemeral` frame without an `ephemeral_sequence` (jarvis/surface/inherent_protocol.py:139-142) and no caller sets one.
- **`server.hello` carries no cadence or config field**: `ServerHelloPayload` is a strict frozen six-field model (jarvis/surface/inherent_protocol.py:168-178) and `RuntimeCapabilities` a fixed eight-field one (:149-165). `TransportAckPayload` (:334-340) is `{snapshot_id?, through_cursor}` and already carries a durable-only ACK.
- The flag lives at config/jarvis.yaml:287-289 (`inherent:` / `v2_sequencer:` / `enabled: false`) under the comment at :279-286. It is parsed by `inherent_v2_sequencer_enabled(runtime.config)` walking plain `Mapping`s (jarvis/runtime/inherent_hub.py:323-347), called once from `start_inherent_view` (:368), which `serve_inherent` invokes at jarvis/runtime/inherent_loop.py:3016-3021 and whose result it plugs in at :3038.
- The trace mechanism is already in the hub: `record_realtime_trace` (jarvis/shared/realtime_trace.py:180), imported at inherent_hub.py:41 and used at :218, :237, :263 and :342. It is bounded, process-local, and explicitly not Event Log truth (jarvis/shared/realtime_trace.py:1-8).
- Test doubles: `_Socket` records every frame and the close but never blocks (tests/integration/test_inherent_sequencer.py:379-402); `_Rig` runs a real Event Log with one sequencer and one hub and takes `recovery_interval_s` / `adoption_deadline_s` (:405-485); `_settle` (:493) and `_ack` (:497) are the helpers. The 0.2 s adoption-deadline case (:694-708) is the only timing test and it uses a real short deadline.
- Swift: `RealtimeStore.apply` folds one event with the pure reducer and hands the effects to a runner (desktop/inherent-swift/InherentRealtime/RealtimeStore.swift:34-37); `reduce` already receives `now: ContinuousClock.Instant` (RealtimeReducer.swift:18-22). Effects leave through `RealtimeEffectRunner` (RealtimeEffects.swift:68-70); the only runner in the tree is `RecordingEffectRunner` (:73-81) and `RealtimeTransportV2.enabled` is `false` (desktop/inherent-swift/InherentCard/RealtimeTransportV2.swift:25), so no ACK reaches a real socket yet. A scheduled effect already has a precedent: `.scheduleLocalFade(groupID:after:)` (RealtimeEffects.swift:63, emitted at RealtimeReducer.swift:466).
- Baselines at 7c4541d: hermetic 885 passed / 64 deselected; Swift 160 tests.

## Target behavior
### Server lanes (D11:777-786, rules 1-5, 10, 12)
- Each `InherentClient` owns three bounded structures instead of one queue: a **control-ack lane** of 32 frames, a **durable/snapshot lane** bounded by both 256 frames and 1048576 total encoded bytes, and an **ephemeral coalescing map** of at most 32 keys. The byte size is the UTF-8 length of the frame the lane was handed, which the hub already has in `_enqueue` (inherent_hub.py:188-190).
- Sender priority is control ACK, then durable/snapshot, then ephemeral (D11:788). **Rule 10 fairness**: at most eight consecutive control frames leave before one ready durable frame does, so a control flood cannot starve durable truth (D11:825-827).
- The client tracks `last_sent_cursor`, `last_acked_cursor`, unacked durable frame count and unacked encoded bytes (rule 5, D11:793-794); the first two already exist (inherent_hub.py:99-100).
- **Rule 3 backpressure** (D11:792): a durable enqueue that would exceed either limit does not drop and does not block. The server best-effort sends a `server.resync_required` protocol frame with `payload.reason = "client_backpressure"` on the control lane and closes that client with the existing 1008 `resync_required` code. The frame is built through the hub's existing `_protocol_frame` (inherent_hub.py:192-205); no new DTO is needed because `ServerEnvelope.payload` is `dict[str, Any]` (jarvis/surface/inherent_protocol.py:130).
- **Rule 9 ack stall** (D11:822-824): no ACK progress for `ack_stall_s` while the durable/snapshot window is non-empty closes that client with the same 1008, reason `ack_stalled`. The existing five-second snapshot adoption deadline (inherent_hub.py:58, :226-229) and its `resync_required` reason are unchanged.
- **Rule 12 ephemeral eviction** (D11:829-833): a 33rd distinct key never silently evicts. The hub enqueues an `ephemeral.clear` frame naming the evicted key, at a strictly increasing `ephemeral_sequence`, before the new key's first frame; if the client's bounded lane cannot preserve that clear-before-new ordering, the client is closed/resynced. Rule 2's audible-tail exception (D11:781-783) is D12's and is not built here.
- **Rule 4 isolation** (D11:791): every close above affects exactly one client. Another client attached to the same sequencer keeps receiving `view.delta` with an advancing `event_cursor`.
- **Catch-up byte budget**: `complete_snapshot` gains a byte budget beside `CATCH_UP_FRAME_BUDGET` (jarvis/runtime/inherent_view_sequencer.py:55, :236-241), defaulting to the same 1048576. A replay over it raises the same way and closes/resnapshots exactly as the frame budget does — never a partial catch-up (D8:582-583).
- **Exception guard**: an unexpected exception inside one client's `_run_snapshot` or inside the sequencer drain closes only the affected client with 1008 and logs once, instead of re-raising out of `_run` and stopping the one producer for everybody (jarvis/runtime/inherent_view_sequencer.py:291-293).

### Client ACK (D11 rules 6 and 8, :796-812, :820-821)
- After a durable batch has been applied on the MainActor, the client returns a cumulative `transport.ack` with `through_cursor` set to the last applied cursor and no `snapshot_id`, matching the shape `TransportAckPayload` already accepts (jarvis/surface/inherent_protocol.py:334-340) and the validation already in `_apply_ack` (jarvis/runtime/inherent_hub.py:166-171).
- Cadence: 25 durable messages or 100 ms, whichever comes first. The observable contract is stronger and is what makes rule 9 safe: **while the socket is live, no applied durable frame stays unACKed longer than `ack_batch_ms`, whatever the arrival pattern — including a burst that stops.** A burst that ends must not leave the window idle and unACKed.
- The snapshot-adoption ACK is unchanged: still exactly one `.sendAck` carrying the snapshot id and `through_cursor` (RealtimeReducer.swift:215).
- **The cadence numbers are Swift constants, not negotiated.** `server.hello` carries no capability or config field able to hold them (jarvis/surface/inherent_protocol.py:168-178, :149-165), so the client uses constants equal to the `ack_batch_messages` / `ack_batch_ms` defaults; adding a hello field is deliberately not done.

### Configuration (no new flag)
- Everything stays under `realtime.inherent.v2_sequencer.enabled` (config/jarvis.yaml:287-289). Flag-off remains byte-identical on the v1 wire and constructs none of this.
- Limits are config keys in a `flow_control` block beside `enabled`, parsed the same plain-`Mapping` way as the flag (jarvis/runtime/inherent_hub.py:323-347) and passed into the hub from `start_inherent_view` (:350-378), with exactly D11's defaults: `control_frames: 32`, `durable_frames: 256`, `durable_bytes: 1048576`, `ephemeral_keys: 32`, `ack_batch_messages: 25`, `ack_batch_ms: 100`, `ack_stall_s: 5`, `control_fairness: 8`.

### Observability
- One trace point per close reason — `client_backpressure`, `ack_stalled`, `catch_up_budget` — through the `record_realtime_trace` call the hub already makes in `_fail` (jarvis/runtime/inherent_hub.py:263-267), by passing distinct reason strings instead of the current generic `resync_required` at :235. No new logging or metrics framework.

## Boundaries and non-goals
- Layers that may change: runtime, L5 (only if `server.hello` gains a field, which it should not), config, Swift client, tests, scripts.
- Must not change: jarvis/surface/inherent_output.py (the v1 broadcaster), jarvis/state/inherent_view.py, jarvis/surface/inherent_presenter.py, the InherentCard v1 files, the D8 snapshot format, the v2 envelope shapes from the v2-envelope-and-identity card, and the v1 wire. No new feature flag. No D11 rule text is rewritten: **if the code must deviate from a D11 rule, stop and report — the card is the contract.**
- **No production ephemeral producer is wired.** Nothing in the daemon emits an ephemeral frame today, and this card adds no producer: the coalescing map and rule 12 are built in the hub's ephemeral enqueue path and exercised only through a test-only emitter. Partial transcript, playback progress and progress hints stay for later cards.
- Non-goals: D12 connection liveness, heartbeats and the separately protected audible-tail state; snapshot page byte budgets beyond the existing 64 KiB paging; any control message the client sends other than `transport.ack`; wiring a real Swift effect runner or flipping `RealtimeTransportV2.enabled`; publishing `surface.response_*` on the committed bus.

## Rejected approaches
- A second feature flag for flow control — the hub rulings fix everything under `realtime.inherent.v2_sequencer.enabled`; a second switch would create a state where the sequencer runs with unbounded queues, which is the bug this card removes.
- Negotiating the ACK cadence through `server.hello` — `ServerHelloPayload` and `RuntimeCapabilities` are strict frozen models with no room for it (jarvis/surface/inherent_protocol.py:149-178), and a negotiated cadence would put a wire-compatibility surface around two integers whose defaults both sides already agree on.
- Dropping or coalescing durable frames under pressure — D11 rule 1 (:790) forbids dropping or reordering durable segments, terminals, action states and confirmation states; the bounded lane must close the client instead.
- Blocking the sequencer or the enqueue on a full lane — D11 rule 4 (:791) says no slow-client condition blocks the sequencer, TTS, playback interrupt or another client.
- "Mark slow" as the terminal policy for a stalled ACK — D11 rule 9 (:824) explicitly rejects it.
- Silently evicting the 33rd ephemeral key — D11 rule 12 (:829-833) requires the ordered `ephemeral.clear` first.
- Sleeping five real seconds in the ack-stall test — the deadline is a config key and the hub already takes an injected `clock` (jarvis/runtime/inherent_hub.py:84, :284), so the case runs on injected time.
- Reusing the generic `resync_required` reason string for every close — ruling 5 needs one trace point per distinct reason, and the smoke canary is the reason B is closed with.
