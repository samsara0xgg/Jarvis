## What the first burn attempt got wrong

The first run reported 2/10. Every failing assertion was the harness's, not the
system's: it inspected `RunTurnResult.events_emitted`, which carries only what
`decide()` itself emitted, while L4 handlers write `action.result_observed`
straight to the connection. Re-verifying against the append-only log — the
stronger source — turned all eight runnable rows green with no code change and
no re-run of the LLM.

One second-order lesson worth keeping: E1's first assertion excluded entries
whose `confidence` was `"config"`, and T4 resolved to a path that is *also* a
configured bookmark. The projection had done exactly the right thing — kept the
config provenance while attaching the resolution's `source_event_id` and alias —
and the assertion called it a miss.
