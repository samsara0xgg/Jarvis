# Reference fidelity review — 2026-09-12

This review uses the user's supplied images and recordings. It does not inspect the Codex application or use its private assets.

- Visible voice group: 270 × 40 logical pixels; text group: 330 × 40. Both expand around the same center. The 372-pixel native window includes transparent space for the transition.
- Main glyphs: contours extracted from reference frames, rendered as 20-pixel SVGs. `scripts/trace-reference-icons.py` records source crops; `scripts/verify.mjs` rasterizes the shipped paths; `scripts/compare-icons.py` produces `evidence/icon-fidelity.png` and mask scores. These scores describe glyph contours only, not overall product fidelity. Compression affects the muted-state sources. The initial badge-occluded bell reconstruction appeared tilted without its badge. The bell now uses a separate, symmetric continuous path (`src/bellPath.ts`), verified without a badge; it is deliberately reconstructed rather than scored as a traced reference match.
- Material: native AppKit background blur, neutral black overlay at 40% by default, reduced border and shadow. Opacity now affects both controls and supporting panels. Native material strength is independently adjustable from 0–100%, and settings persist in the prototype profile. It follows desktop color. Native window-only screenshots omit desktop compositing, so they cannot prove a material pixel match.
- Motion: 80 ms centered composer morph, small hover fill and press compression, and 180 ms ease-out notification transitions. A 60 fps resample shows the reference text content switching around 13.967–14.000 s; the old native material briefly lags behind the content. This prototype uses a short synchronized morph rather than reproducing that lag. Reference notification contrast decays from 12.850 to 13.033 s; runtime opacity samples now follow a similar curve. The initially declared exit CSS did not actually fade because the entering animation overrode it; runtime sampling caught this, and a continuous transition with @starting-style fixes it. Native material rectangles and inherited opacity follow the transitions. Reduced-motion mode disables animation.
- Computer Use found a real acceptance failure: the renderer received a drag but polling the OS cursor did not move the window. Dragging now uses pointer-event screen coordinates, flushes the release position, and cleans up capture loss. A microphone drag from (147,36) to (207,66) moved the native window from (570,337) to (630,367), preserving the unmuted state. A subsequent click muted it. Notification drag also preserved the expanded state; see `evidence/cua-drag-notification.json`. This run had one 2× display; physical multi-display acceptance remains separate.
- Audio candidates are now integrated for voice entry, microphone on/off, and speaker on/off. `scripts/prepare-feedback.py` builds them by retaining measured frequency bands from the supplied recording, correcting the AAC start timestamp, and applying attack/release fades. Default output is deliberately quiet; settings provide an independent master switch and volume. These are filtered candidates, not recovered original application sound assets. UI-to-audio timing in the recording is not exact, and earcon mappings remain provisional. Playback is verified through real AudioContext decoding/start events with native output muted; no sound plays on launch or hover. Rapid playback cancels the previous cue; idle contexts suspend. Wave files have zero-valued boundaries, near-zero DC offset, and no clipped samples. The model still cannot verify auditory similarity.
- Original audio comparison material: Three original-audio audition clips are in `design/analysis/`: voice entry (original 7.35–8.30 s), microphone switching (comparison 6.10–7.60 s), and speaker switching (original 10.95–12.00 s). Only boundary fades were applied. These recordings may contain room/click noise; the model cannot hear them. The unfiltered clips remain available for later listening comparison. No exact sound-match claim is made.
- Center waveform v1 is implemented from the approved filament concepts: damped geometry changes, phrase swells, inward thinking contraction, and a quiet muted trace. It preserves the compact capsule. The settings offer a complete 20-second audition, individual states, and a persisted theme color. It uses simulated energy, not microphone samples. Reduced-motion preferences produce a stable drawing; hidden renderers stop their animation loop. See `evidence/presence/verification.json`.

Additional acceptance: notifications sit 12 logical pixels below the controls, without the old hidden status row taking layout space. Single-card dismissal collapses before removal. Right-click settings work while notifications remain visible. Closing settings/details releases native focus or restores text input as appropriate. Preferences survive an actual renderer reload. The compose-button drag moved the window by exactly (-20,+10) without entering text, in a nonfocusable window; see `evidence/cua-drag-compose.json`.
